# 口令引擎

改 `coach/`、`scenes.json`、候选选择、两步状态机或回归样张时读本文件。场景和口令内容以需求第 8、11 节为准。

## 模块边界

`coach/` 是无 Android UI 的 Kotlin/JVM 模块。它可以定义可序列化信号、场景、候选口令和指导会话，但不能依赖 Activity、Compose、CameraX、Bitmap 或 `Context`。Android 只输入信号并消费输出；以后 iOS 可复用 JSON/字段约定，而不是相机壳。

## P-1 候选与会话

- 用户意图是硬过滤条件。当前 P-1 只允许 `close_up`、`person_with_scenery` 和三个 SceneId。
- 场景匹配优先级是：用户意图 > 后摄/人数等硬信号 > 更具体场景 > 通用兜底。用户手选意图后，本轮自动选择不能覆盖。
- 引擎每轮最多产生构图、光/曝光、姿势三个不同 channel 的候选；每条都有 `shooter` 或 `subject` audience。P-1 不输出 `proxy`。
- 会话只展示最多两个必做动作：先一个 shooter，再一个 subject。动作稳定改善、失效、超时或跳过后推进；两步后进入 Ready。
- “再优化一下”每轮最多一个可选动作，不显示 3/3、不计入两步预算；快门在任意指导阶段合法。
- 候选约每 300ms 输入；变更须满足 600ms 或连续三帧稳定。五秒内禁止相反方向提示，TTS 同句须节流。
- 没有高置信度候选时直接 Ready，不能无限显示“AI 思考中”。

## 内容规则

- 只使用需求第 11.5 节短口令核和当前启用场景的特有句；不按性别、网红风格或模板包扩库。
- 口令必须是当前取景器可执行的动作，例如点脸、EV、已验收焦段、走近、放平、靠近软光。
- 禁止光圈、ISO、白平衡、开尔文、焦距倒数、评分、百分比、外貌评价和 100% 对齐。
- `faceCount != 1` 不得进入 P-1 单人场景/姿势；如输出回退，只能是水平、切边或曝光等安全动作。
- P0/P1 场景即使预写在 JSON 中，也必须由版本开关排除在 P-1 匹配外。

## 场景与回归

修改 `scenes.json`、阈值、优先级或去抖后，至少验证：

1. 三个 P-1 场景各自应该进入与不应进入。
2. 必须出现与禁止出现的提示。
3. 用户意图锁、两步预算、跳过、随时快门、可选第三条。
4. 两张脸、无脸、姿态缺失、镜头疑似遮挡和相反方向防抖。
5. TTS 只取 subject，proxy 和禁用术语不会流出。

项目已有 `PMinusOneRegressionTest`、`CoachRulesTest` 和 `GuidanceSessionTest`；优先扩展行为测试与 fixture，不要写只匹配标题、固定 JSON 排版或实现私有方法的脆弱测试。真机样张期望进入仓库，修改规则后必须重跑对应 fixture。
