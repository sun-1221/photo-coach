## 1. 产品结论

### 1.1 一句话

面向拿小米 14 Pro 帮伴侣或朋友拍照的新手的拍中教练：先确认拍摄意图，不打分、不等待完美匹配，默认只给拍摄者和被拍者各一个动作，用户随时可以按快门，并在 30 秒内保存一张真实照片。

### 1.2 要解决的问题

用户会打开系统相机和按快门，但经常遇到：

- 不知道站在哪里、手机应该往哪移动。
- 不知道人物与地标应各占多少画面。
- 不知道该怎样简单、自然地指挥被拍者。
- 建议太多、术语太重时反而错过拍摄时机。
- 第三方相机如果黑屏、卡顿或保存失败，任何指导都失去价值。

本产品首先解决“如何更快完成一次满意的拍摄”，不是建立摄影课程、姿势商城或评分游戏。

### 1.3 核心产品原则

| 原则 | 产品约束 |
| --- | --- |
| 拍下来优先 | 快门始终可用；指导不能锁快门 |
| 最多两步 | 默认一个拍摄者动作 + 一个被拍者动作，之后直接进入“可以拍了” |
| 一次一件事 | 主界面同一时刻只显示一个主要动作 |
| 用户意图优先 | 用户选择后，自动识别不能覆盖本次选择 |
| 不追分 | 不显示美学分、匹配分、准备度分或 100% 对齐 |
| 真实成片 | 使用系统/厂商计算摄影能力；不生成换脸、换姿势或替换原片 |
| 主路径离线 | 意图、两步指导、快门和保存不依赖网络 |
| 隐私最小化 | P-1 只申请相机权限；端侧分析，不识别身份、不建人脸库 |
| 先验证再扩展 | P-1 未过线，不把完整 P0 或 P1 扩展混入 P-1；单独批准的 P1 必须独立开关、独立验收且不得计入 P-1 Go 证据 |

### 1.4 已拍板

| 问题 | 决定 |
| --- | --- |
| 首个平台 | Android；P-1、P0 和 P1 只验收小米 14 Pro |
| 其他机型 | P-1、P0、P1 均不做兼容承诺，后期再决定是否立项 |
| 第一角色 | 拍摄者是主用户，App 帮他指挥被拍者 |
| 首个任务 | 单人人物特写和“人带景” |
| 提示方式 | 拍摄者动作卡始终显示；中文语音和被拍者字幕可独立开关，默认同时开启 |
| 第一入口 | 打开后直接进入教练取景器，不设模板首页 |
| 提示来源 | 端侧感知 + 内置规则库；云端只做 P0 可选“再讲细” |
| 相机控制 | 点按对焦、EV、可用的光学焦段、闪光状态、屏幕与音量键快门 |
| 成片 | 保存到系统相册可见目录，无水印 |
| 代拍 | P-1 不做；完整 P0 才加入简化交接界面 |
| 前摄、合影、角色切换 | P-1 不做；按第 4、13、14 节推进 |

## 3. 产品假设与继续投入门槛

### 3.1 待验证假设

> 对首个目标用户，如果 App 先确认“人物特写 / 人带景”，默认只要求一个拍摄者动作和一个被拍者动作，不显示分数、不等待完美匹配，那么用户能在 30 秒内完成一张比系统相机和静态提示卡更受双方偏好的照片，并愿意在下一次真实拍摄时再次使用。

实时语音、伴侣帮拍、陌生人模式、姿势叠图和端侧分析都已有重叠产品。第一版真正要验证的是：动态指导是否比静态提示卡有增量，以及“两步就拍”是否让用户愿意复用。

### 3.2 P-1 对照实验

- 至少 20 名符合[首个目标用户](requirements/interaction-guidance-and-scenarios.md#21-首个目标用户)定义的首次用户。
- 每人完成室内窗边、室外人带景、逆光人像三个场景。
- 同一设备、同一场景在用户内随机轮换三种条件：系统相机、静态提示卡、动态教练。
- 静态卡与动态教练使用相同的第三方相机管线、初始参数和保存方式；差异只允许来自“是否根据当前画面动态选择提示”。
- 静态卡不分析画面，但仍按与动态教练相同的 1/2、2/2 顺序依次显示一条固定拍摄者动作和一条固定被拍者动作，避免用不同界面节奏干扰实验。
- 每次更换条件时重新站位和构图，避免直接复制上一轮动作。
- 保留原始人数、拍摄次数、失败数、中位耗时和盲评选择，不能只报告百分比。
- 研究员要求的重复测试不计入自然复用。

### 3.3 成功指标

| 维度 | P-1 门槛 | 计算方式 |
| --- | --- | --- |
| 30 秒完拍 | 首次用户保存成功率 ≥ 90% | 从取景器可操作到写入系统相册；不含用户主动退出 |
| 两步预算 | ≥ 80% 的成功拍摄在两个必做动作内完成 | 最多一个 shooter 动作 + 一个 subject 动作；设备错误不计入 |
| 系统相机对比 | 盲评偏好教练照片的比例 ≥ 60% | 系统相机与动态教练照片乱序二选一；拍摄者、被拍者分别记录 |
| 动态增量 | 相比静态卡，盲评偏好至少高 10 个百分点，或中位完拍时间至少缩短 20% | 两项至少通过一项 |
| 自然复用 | 无提醒 D7 真实拍摄再次打开比例 ≥ 30% | 不把研究安排的第二次打开算入 |
| 口令有效 | 可机器判断的口令在 5 秒内使目标信号改善 ≥ 70% | 水平、人脸占比、脸部亮度等；姿势句人工抽检 |
| 错误口令 | 无法执行、听众错误、同屏冲突合计 ≤ 5% | 真机录像复核 |
| 不打扰 | 被拍者认为语音“尴尬或打扰”的比例 ≤ 20% | 拍摄后单题反馈 |
| 性能 | 打开相机 p95 < 1 秒；内置提示 p95 ≤ 300ms | 冷启动、热启动和连续取景分别记录 |
| 保存可靠性 | 快门到系统相册写入成功率 ≥ 99.5% | 真机连续拍摄；失败可见且可重试 |
| 离线 | 飞行模式主路径通过率 100% | 意图 → 两步指导 → 快门 → 相册 |

### 3.4 Go / No-Go

- 第 3.3 节全部通过，才把完整 P0 当发布候选。
- 动态教练不胜过静态卡：停止扩大实时分析，评估改成更简单的拍照清单产品。
- 成片稳定输给系统相机：停止扩教练功能，先修成片链路，或改成不负责拍照的系统相机伴随方案。
- D7 自然复用不过线：不得用滤镜、评分、签到或姿势商城补救核心需求不足。
- 语音打扰超标：停止默认外放，改为首次选择或默认静音后重新验证。

### 4.5 P1 第二阶段扩展（ApprovedSeparate）

2026-09-01 将以下能力作为小米 14 Pro 的独立 P1 第二阶段需求登记。它们不进入 P-1 对照实验，不改变完整 P0 的 GateLocked 状态，也不能用代码路径或自动化结果替代目标机验收：

- 特写、半身、全身、坐姿、走动和单人互动六类姿势库；每条口令必须有可观察触发、退出条件、低置信度回退和明确的自动完成边界。两张脸以上继续禁止单人姿势匹配。
- 构图、关节裁切、用光、焦段/距离、背景、夜景、运动和多人安全回退等摄影技巧；只建议当前公开能力和画面证据可执行的动作，不伪造机位高度、光学焦段或场景理解。
- 在现有十二种风格上增加场景化推荐、强度建议、最近使用和收藏；原图始终第一且不被覆盖，推荐不得自动套用。
- 人像场景只允许保守限制全局风格强度和检查脸部区域前后变化；在完成脸颊采样、肤色范围、受控光照与目标机样张验收前，不宣称局部“肤色保护”。
- 面部只输出转头、侧倾、睁眼等可观察动作；不从笑容、皱眉或其他面部运动推断开心、紧张、疲惫、愤怒等情绪，不做身份、年龄、性别或外貌评分。
- 保存增加 pending/发布后资产校验、方向/EXIF/相册可见性检查和逐阶段幂等恢复；Motion Photo 继续无声、单主文件、SDR JPEG 和普通 JPEG 回退。
- 连续取景、姿势分析、风格处理、连拍和 Live 接受目标机热状态驱动的分级降载；任何降载都不得取消普通快门、实时预览或已经捕获原片的保存。

具体姿势、技巧、触发和退出边界见[交互、指导与场景规格第 11.6 节](requirements/interaction-guidance-and-scenarios.md#116-p1-第二阶段姿势与摄影技巧库)，风格、保存、Motion Photo 和热策略见[P1 创意层第 12.2.1 节](requirements/p1-creative.md#1221-p1-第二阶段强化)，FR/UX 与证据状态分别以[需求追踪矩阵](traceability/requirements-matrix.md)和[分阶段验收](acceptance/acceptance-plan.md)为唯一权威。

## 5. 跨版本硬约束

以下规则跨 P-1、P0 与已批准 P1 生效；某阶段未获准时，只保留规则，不因此进入交付范围。

- P-1 主路径只验收小米 14 Pro 后摄单人、人物特写/人带景、三个场景包、一个 shooter 必做动作加一个 subject 必做动作。候选最多三条不等于同屏或必做三步；“再优化一下”最多一条且不算必做步骤。
- 快门只因相机不可用或正在捕获而暂时禁用；指导、分数、网络和阈值不得锁快门。P-1 意图、指导、捕获和保存必须在飞行模式工作。
- 普通相机链路必须同时保留 Preview、ImageAnalysis、ImageCapture；分析只保留最新帧。唯一批准的四用例例外是用户显式开启的无声 P1 Live，失败后可见回退普通 JPEG；Extensions 不能以卸载分析为代价。
- 快捷焦段只来自标准 CameraX/Camera2 实际能力与小米 14 Pro 真机标定；不得硬编码 2x、把数码裁切称作光学镜头、读取厂商传感器 ID，或把未验证焦段写成通过。
- Face/Pose 只产生端侧构图与口令信号，第 4.6 节另允许复用 Face 数值关键点作本地美颜；禁止身份识别、embedding、人脸库、外貌评分和姿势分。两张脸以上不得进入单人姿势匹配。
- P-1 只申请 CAMERA，不新增登录、麦克风、定位、读取整本相册、后台上传或持续重试。
- 已批准 P1 创意层不得改变 P-1 对照实验和 Go 指标。每次捕获使用不可复用 captureId；默认发布原片、私有保存配方，效果 JPEG 仅在明确另存或用户主动开启自动双保存时生成；分阶段恢复只重试失败阶段；无声 Motion Photo 是单一主文件，失败回退普通 JPEG且不得重复发布。
- 已批准 P1 第二阶段姿势与摄影技巧继续服从一次一个主要动作、最多两个必做动作和随时快门；坐姿、走动、互动、肤色保护、复杂表情及 HyperOS Motion Photo 兼容性若缺少目标机证据，必须标为需校准或 NotRun，不能写成已承诺准确。
- Scope、Delivery、Verification 必须分别报告。代码路径、自动化通过和设备通过是三个不同事实；Unknown/NotRun 不能写成通过。

## 10. 约束、隐私与信任

### 10.1 产品与成片约束

- 产品不自研 ISP、RAW、LUT 或生成替换；第 4.6 节独立批准的局部纹理平滑是美颜的唯一例外，P-1/P0 和既有全局风格仍无美颜。
- 成片优先使用兼容的系统/厂商计算摄影；无法与实时分析共存时回退标准拍照。
- 口令出现的动作必须能在取景器执行。
- 自动快门 P-1 不存在；P0 即使实验也默认关闭，并设置最多三张、冷却和立即停止。
- 第一版只验收小米 14 Pro 的竖屏和横屏。

具体 CameraX、ML Kit、扩展兼容和 API 结构以 [architecture.md](architecture.md) 为准。

### 10.2 权限与数据

- P-1 只申请 CAMERA。
- 不申请麦克风、定位、联系人或读取整本相册。
- 保存只插入本 App 新拍的照片；最近照片只使用本次写入得到的 URI。
- 默认只做端侧人脸框、关键点和单人姿势，不做人脸比对、不存身份模板。
- P-1 研究事件只记录时间、意图、提示 ID、完成/跳过、快门、保存结果和匿名会话编号；不记录预览帧、人脸坐标、照片内容或身份。
- P0 云端讲解单独同意，单帧按需上传，用完不落库；撤回后不得后台重试。
- 上架前以真实安装包核对网络和第三方 SDK 行为，商店数据安全披露必须与实际一致。

涉及人脸和儿童的能力上线前，须按届时有效法规完成专项法律复核和个人信息保护影响评估；不能仅依赖本文中的历史法规名称。

### 10.3 可靠性与信任

- 拍中教练主路径免费可用，不能锁意图、基础口令、快门或保存。
- [短口令核](requirements/interaction-guidance-and-scenarios.md#115-短口令核)与场景特有句全部免费。
- 核心能力不依赖登录。
- 不默认周订阅；若后期收费，优先买断或年付，并明确免费边界。
- 原片无水印，用户能在系统相册找到。
- 黑屏、自动拍停不下和保存失败是信任阻断问题，优先级高于增加场景和姿势。
