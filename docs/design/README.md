# Photo Coach 界面设计系统

> 状态：v1.0（2026-09-04）
> 适用范围：Android 端相机授权、权限异常和实时取景器界面。

本文档是 Photo Coach 界面的设计与验收基线。产品需求决定“做什么”，本文档决定“如何呈现”；现有代码若与本文档冲突，应先记录差异，再由产品与开发共同确认迁移方式。

## 1. 体验目标

Photo Coach 的核心不是展示复杂参数，而是在用户准备拍照的几秒内，提供清晰、可信、不会遮挡主体的指导。

界面必须同时满足以下目标：

1. **取景优先**：相机画面始终是主视觉，辅助界面只占必要空间。
2. **一眼可懂**：任何时刻只突出一个主要建议和一个主要操作。
3. **稳定可信**：分析中、无建议、失败和权限异常都应有明确状态，不让用户猜测。
4. **单手可达**：手机竖屏时，主要操作位于下半屏；关键触控区域不小于 48dp。
5. **环境友好**：户外强光、暗光以及复杂画面下，文字和控件仍需保持可读。

## 2. 信息层级

界面内容按以下优先级排列。低优先级内容不得抢占高优先级内容的视觉注意力。

| 层级 | 内容 | 呈现规则 |
| --- | --- | --- |
| P0 | 实时取景画面 | 全屏或占据最大可用区域，不使用永久大面积遮罩 |
| P1 | 当前拍摄建议 | 同一时间只展示一条，短句、动作导向、可立即执行 |
| P2 | 拍摄状态与关键操作 | 使用稳定位置；状态变化不应导致布局跳动 |
| P3 | 参数、解释和辅助信息 | 默认弱化；仅在用户需要时展开或进入后续层级 |

建议文案采用“动作 + 对象/方向”的形式，例如“向左移动一点”“降低机位”。避免把模型术语、置信度或内部错误直接暴露给用户。

## 3. 页面结构

### 3.1 相机授权页

授权页只承担解释价值和触发系统授权两项任务。

- 页面保留一个主标题、一段不超过三行的说明和一个主按钮。
- 主按钮使用明确动作“允许使用相机”，不得使用“继续”“确定”等模糊词。
- 隐私说明作为次要信息，视觉权重低于主操作。
- 内容区在紧凑宽度下使用 16dp 外边距，在中等及更宽窗口中限制最大宽度，避免文字和按钮被横向拉伸。
- 插图或图标只能帮助解释相机用途，不能成为授权前置交互。

### 3.2 权限拒绝页

根据系统是否允许再次请求权限，显示不同动作：

- 可再次请求：主按钮为“重新授权”。
- 需前往系统设置：主按钮为“打开设置”，并说明返回应用后会自动继续。
- 页面始终保留问题说明和恢复路径，不使用只有图标的操作。
- 不显示无法解决问题的装饰性错误代码。

### 3.3 实时取景器

取景器由四个稳定区域构成：

1. **预览层**：实时相机画面，填满主内容区域。
2. **引导层**：构图线、方向提示或主体框，只表达当前最重要的空间关系。
3. **状态层**：分析中、暂停、异常等短状态，位置固定且不遮挡主体中心。
4. **操作层**：当前建议、主要操作和必要的辅助入口。

操作层应使用渐变或局部表面保证可读性，避免在整个预览上添加深色蒙层。建议更新时保持容器尺寸稳定，并使用轻量过渡替换内容。

## 4. 自适应布局

布局依据应用窗口而非物理设备型号判断。横竖屏、分屏和折叠状态变化后必须重新计算可用空间。

| 可用窗口 | 主布局 | 关键约束 |
| --- | --- | --- |
| 紧凑宽度 `< 600dp`、高度 `>= 480dp` | 取景器全屏，状态置顶，建议与操作置底 | 左右安全边距 16dp；底部高度上限不得采用未经产品决议的独立数值，CP-01 决议前同时保留交互规格“约五分之一屏幕高度”和 UX-15“约四分之一取景器高度”两套口径，均不得标记为唯一规范或通过阈值 |
| 紧凑高度 `< 480dp` | 取景器与右侧操作区并列 | 操作区建议宽 280–360dp；不可把竖屏底部面板原样压缩到横屏 |
| 中等宽度 `600–839dp` | 取景器 + 支持面板 | 支持面板建议宽 320–360dp；预览保持连续且不被拉伸变形 |
| 展开宽度 `>= 840dp` | 取景器为主、固定宽度支持面板为辅 | 面板不随窗口无限拉伸；说明文字行宽不超过约 60 个中文字符 |

当前手机版本至少需要完整支持前两种布局。中等和展开宽度属于增强目标，但实现不得锁定方向、屏幕比例或假定固定设备尺寸。

### 4.1 竖屏区域关系

```text
┌──────────────────────────┐
│ 安全区 / 轻量状态         │
│                          │
│        实时取景器          │
│     构图与方向引导层       │
│                          │
│  当前建议（单一、短句）    │
│  主要操作 + 必要辅助入口   │
└──────────────────────────┘
```

### 4.2 紧凑横屏区域关系

```text
┌────────────────────┬──────────────┐
│                    │ 状态          │
│     实时取景器      │ 当前建议      │
│     引导层          │              │
│                    │ 主要操作      │
└────────────────────┴──────────────┘
```

横屏操作面板应保持完整的触控尺寸；空间不足时先减少说明文字和次要入口，再考虑滚动，不能缩小关键按钮。

## 5. 布局令牌

所有页面使用同一套 4dp 基础网格。

| 令牌 | 值 | 使用场景 |
| --- | ---: | --- |
| `space-1` | 4dp | 图标内部、紧密关联元素 |
| `space-2` | 8dp | 图标与文字、同组控件 |
| `space-3` | 12dp | 小组件内部间距 |
| `space-4` | 16dp | 页面边距、标准卡片内边距 |
| `space-6` | 24dp | 内容组之间 |
| `space-8` | 32dp | 页面主要区块之间 |

其他布局规则：

- 页面水平边距默认 16dp；宽裕空间下可提升为 24dp。
- 同一组件内部只使用相邻两个间距等级，避免视觉节奏零碎。
- 操作按钮最小高度 48dp，主按钮建议 52–56dp。
- 图标视觉尺寸通常为 20dp 或 24dp，点击区域仍需达到 48dp。
- 卡片圆角使用 16dp；大面板使用 24dp；胶囊状态使用全圆角。
- 文字内容区设置最大宽度；不能依靠 `fillMaxWidth` 把按钮或段落无限拉宽。

## 6. 颜色与层级

颜色通过语义角色使用，不允许在业务组件中散落无含义的色值。具体色值由 `PhotoCoachTheme` 统一提供。

| 角色 | 用途 | 要求 |
| --- | --- | --- |
| `surfaceBase` | 页面与相机外的基础背景 | 深色、中性，不与预览争夺注意力 |
| `surfaceRaised` | 卡片、底部/侧边操作区 | 与基础背景有可感知但克制的层次 |
| `surfaceOverlay` | 预览上的状态与建议容器 | 应配合局部渐变或半透明表面保证稳定对比度 |
| `textPrimary` | 主标题、当前建议 | 满足正文可读性，强光下仍清晰 |
| `textSecondary` | 说明、次要状态 | 不得低到难以辨认 |
| `accentAction` | 主按钮、当前选中状态 | 每屏集中使用，不能同时高亮多个竞争动作 |
| `feedbackPositive` | 已满足的拍摄条件 | 不仅依赖颜色，还需图标或文字 |
| `feedbackWarning` | 需要调整但可继续 | 避免与致命错误使用相同视觉 |
| `feedbackCritical` | 权限、相机或流程不可继续 | 提供恢复动作，不作为纯装饰色 |

正文文字与背景的对比度目标不低于 4.5:1；大号文字不低于 3:1。相机预览内容不可控，因此叠加文字必须依靠容器、描边、阴影或局部渐变取得稳定对比度。

## 7. 字体层级

| 样式 | 建议规格 | 用途 |
| --- | --- | --- |
| Display | 28–32sp / 紧凑行高 | 极少量品牌或完成态标题 |
| Title | 20–24sp / 1.2–1.3 | 页面标题、授权标题 |
| Coach | 18–20sp / 1.3 | 当前拍摄建议，最多两行 |
| Body | 16sp / 1.4–1.5 | 正文、按钮文字 |
| Label | 14sp / 1.3 | 状态、辅助操作 |
| Caption | 12sp / 1.3 | 非关键补充信息，不承载必要操作说明 |

- 不使用全大写英文作为主要中文界面标签。
- 最小正文尺寸为 14sp；系统字体放大后允许布局换行或滚动。
- 数字参数使用等宽数字特性时，也必须配有可理解的名称与单位。

## 8. 组件规范

### 8.1 当前建议卡

- 一次只显示一条建议。
- 首行是动作句，最多两行；解释信息默认不超过一行。
- 状态切换保持卡片位置和大致高度稳定。
- 没有可靠建议时显示中性状态，例如“正在观察画面”，不得制造虚假精确度。
- P1 参数详情如需展示，应作为可展开次级内容；其信息架构在产品决策确认前不得侵占 P0 建议区域。

### 8.2 主操作按钮

- 每个页面最多一个强调样式主按钮。
- 标签使用明确动词；加载时保持原宽度，防止布局跳动。
- 禁用状态需要解释原因，不能仅降低透明度。
- 成功、失败和处理中状态应具备文本或语义描述。

### 8.3 状态胶囊

- 用于“分析中”“已暂停”等短状态，不承载长句。
- 位置固定，不因文字长度在屏幕中心漂移。
- 动态指示应尊重系统“减少动态效果”设置，并配有静态文本。

### 8.4 构图引导层

- 线条应清晰但不覆盖主体细节；默认使用半透明中性色。
- 只有当前建议相关的方向或区域使用强调色。
- 同屏不叠加多套网格、箭头和边框。
- 引导层不接管触摸事件，也不影响相机对焦等原生交互。

## 9. 状态与反馈

| 状态 | 必须呈现 | 禁止做法 |
| --- | --- | --- |
| 初始化 | 简短稳定提示；预览可用后自动消失 | 长时间空白或全屏加载动画 |
| 分析中 | 轻量状态，可继续取景 | 阻断预览或反复闪烁 |
| 有建议 | 一条可执行动作 + 必要引导 | 同时堆叠多条建议 |
| 暂无建议 | 中性反馈，保持用户信心 | 把“无结果”显示成错误 |
| 权限被拒 | 原因 + 唯一恢复路径 | 循环弹出权限请求 |
| 相机不可用 | 简明原因 + 重试/退出路径 | 暴露异常堆栈或内部错误码 |
| 离线/服务失败 | 说明受影响能力；保留仍可用功能 | 在没有必要时完全退出取景器 |

提示变化不应超过用户可跟随的速度。短时间内连续生成多条建议时，应去重、合并或延迟替换，避免界面和语音互相追赶。

## 10. 动效与触觉

- 建议替换：使用 150–220ms 的淡入淡出或小距离位移。
- 页面进入：控制在 200–300ms，不使用与拍摄任务无关的大幅缩放。
- 循环动画：只用于确实仍在进行的状态，且面积与亮度保持克制。
- 触觉反馈：仅用于用户主动操作、明确状态切换或成功确认；分析结果自动刷新不触发震动。
- 尊重系统动画缩放与减少动态效果设置；关闭动画后功能和信息层级保持完整。

## 11. 无障碍与可用性验收

以下要求属于发布门槛：

- 所有可交互元素的可聚焦触控区域至少为 48dp × 48dp。
- 图标按钮提供准确的 `contentDescription`；纯装饰图形不重复朗读。
- TalkBack 顺序遵循视觉阅读顺序，取景器装饰层不进入焦点链。
- 信息不只依赖颜色，警告和成功状态同时使用文字或图标。
- 正文与背景对比度至少 4.5:1；大号文字至少 3:1。
- 字体缩放到 200% 时，关键文案和主操作仍可访问，不发生不可恢复的裁切。
- 横屏与分屏状态下，主要操作不被系统栏、刘海或显示切口遮挡。
- 自动更新内容避免频繁抢占无障碍焦点；重要变化使用合适的语义通知。

## 13. 设计验收清单

每次界面改动至少检查：

- [ ] 首屏是否能在 3 秒内看懂当前任务和主要操作。
- [ ] 相机画面是否仍是最大、最清晰的视觉区域。
- [ ] 是否只突出一个主要建议和一个主要操作。
- [ ] 360×640dp 与常见手机竖屏下没有遮挡、裁切或不可达操作。
- [ ] 紧凑横屏高度 `< 480dp` 时采用横向结构，触控尺寸没有缩水。
- [ ] 系统字体 1.0×、1.3×、2.0× 下关键内容可读。
- [ ] 深色/复杂预览背景下叠加文字对比度稳定。
- [ ] TalkBack 标签、顺序和状态反馈正确。
- [ ] 加载、无建议、权限拒绝、相机失败等状态都有恢复路径。
- [ ] 截图测试覆盖竖屏、横屏以及关键异常状态。

## 14. 尚待产品确认

以下内容保留为显式决策点，确认前不应由实现细节暗中决定：

1. **CP-01：底部操作区高度**——采用严格固定高度，还是在最大占比约束内按内容自适应；此前设计草案出现的 `38%` 未经决议，属于非规范探索值，不得用于实现门禁或验收结论。
2. **CP-03：P1 参数卡的信息架构**——作为建议卡内的可展开详情，还是独立的次级面板。

决策时优先比较主体遮挡比例、横屏可用性、字体放大后的可达性和建议理解速度，并把结论同步到产品规范、验收标准和实现测试。
