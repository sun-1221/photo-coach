## 1. P-1 端到端用例

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| UX-01 首次同意 | 新安装后打开 | 先看到端侧分析说明，再出现系统相机权限 |
| UX-02 拒绝权限 | 拒绝 CAMERA | 不黑屏；显示原因和系统设置入口 |
| UX-03 意图锁定 | 选择“人带景”后让脸变大或变小 | 本次会话不自动改回人物特写 |
| UX-04 两步指导 | 正常完成或跳过两个动作 | 只出现 1/2、2/2；满足最低可拍条件时显示“可以拍了”，否则显示“随时可拍”且快门仍可用 |
| UX-05 提前快门 | 在 1/2 或 2/2 时按快门 | 立即捕获，不弹拦截提示 |
| UX-06 无建议 | 已可靠识别一名单人人物，但没有高置信度改进建议 | 1.5 秒内结束观察；满足最低可拍条件时显示“可以拍了”，否则显示“随时可拍”，不循环加载且不锁快门 |
| UX-07 提示方式 | 依次选择语音+字幕、仅语音、仅字幕、提示关闭并重启 App | 四种组合立即生效；设置跨启动保持；拍摄者动作卡始终可见 |
| UX-08 目标机焦段 | 在小米 14 Pro 切换所有已验收快捷焦段 | 标签、预览视角和成片一致；未验收倍率不显示，不建议数码猛拉 |
| UX-09 保存成功 | 连续拍照 | 每张都给可见成功反馈，系统相册可见无水印原图 |
| UX-10 保存失败 | 模拟写入失败 | 保留错误与“重试保存”，不能静默丢图 |
| UX-11 飞行模式 | 断网后完整拍摄 | 意图、指导、快门和保存全部可用 |
| UX-12 旋转 | 竖屏与横屏分别完成一张 | 控件不重叠，快门与跳过始终可达 |
| UX-13 缩放 | 在小米 14 Pro 上双指放大再缩小 | 预览连续响应，1x 重置可用，不出现未经验收的快捷焦段按钮 |
| UX-14 最近照片 | 保存成功后点击缩略图 | 打开系统图片查看器；无可用查看器时给出可见提示 |
| UX-15 竖屏紧凑布局 | 在小米 14 Pro 竖屏完成一张 | 操作区保持两排且默认字号下不超过约四分之一取景器高度 |
| UX-16 字幕生命周期 | 仅字幕模式完成、保持、跳过和更换被拍者动作 | 字幕不按 2.5 秒消失；动作完成/失效、替换、跳过、拍照或关闭字幕时正确清除 |
| UX-17 实时口令 | 连续改变远近、水平和单人姿势，并保持每次变化超过 600ms | 旧口令完成或失效后不残留；新口令稳定后更新；单帧抖动不跳字；同句和反向口令满足限流 |
| UX-18 AE/AF 锁定 | 长按人物后改变构图，再点“解除” | 锁定成功/失败和解除均有文字状态；解除后恢复自动；重绑不会虚报仍锁定 |
| UX-19 构图辅助 | 分别关闭网格和水平仪并重启 | 对应叠线立即消失，另一项不受影响；重启后保持 |
| UX-20 倒计时 | 选择 3 秒/10 秒，用屏幕与音量键触发并中途取消 | 数字逐秒可见，到零只拍一张；再次按快门取消；设置跨启动保持 |
| UX-21 画幅 | 在 4:3 与 16:9 间切换并各拍一张 | 三用例按同一画幅策略重绑，预览不黑屏，成片画幅匹配选择 |
| UX-22 拍摄偏好 | 对焦优先、拍摄优先各连续拍摄 | 分别使用质量优先和低延迟捕获；实时分析与保存均不中断 |
| UX-23 能力模式 | 枚举并逐一切换界面列出的模式 | 只列出可与分析共存的模式；任一绑定失败回到普通拍照并可继续拍 |
| UX-24 设置恢复 | 修改全部新增设置、重启，再一键恢复默认 | 重启保持；一键恢复网格/水平仪开、倒计时关、4:3、对焦优先、自动模式和语音+字幕，不清除相机说明同意 |
| UX-25 镜头检查 | 连续遮挡镜头、解除遮挡，再拍普通暗景 | 连续稳定后才显示“可能被挡住或弄脏”；解除后清除；普通暗景不误报 |
| UX-31 未识别人物 | 分别遮挡脸但保留可靠上半身、同时遮挡 Face/Pose、再恢复露脸 | Pose 可靠时仍能更新保守姿势口令；两者都不可靠时显示并播报“请露出脸，或靠近一点”，恢复后稳定替换；不得误报“可以拍了” |
| UX-32 长屏满幅预览 | 在小米 14 Pro 竖屏切换 4:3 / 16:9 | 预览延伸到紧凑底部操作区背后，操作区上方没有大块黑色空带；叠线、点按对焦和分析坐标与可见裁切一致 |
| UX-38 保守感知边界 | 构造真实脸框明暗差、仅改变脸框高度、低微笑概率、单帧髋/脚几何和两张脸画面 | 只有真实脸框内外亮度差触发逆光；位置、低微笑和单帧重心不产生纠正；多人只出现水平、切边或严重曝光提示，不出现单人姿势 |

## 2. 已批准 P1 创意层用例

这些用例不进入 P-1 对照实验，不改变 P-1 Go/No-Go，也不能用来扩大完整 P0。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| UX-26 十二种风格 | 依次切换十二种风格、切回原图并预览/另存 | 预览立即可撤回；预览/编辑/导出矩阵确定一致；默认不生成效果 JPEG，明确另存后才得到兼容 SDR 副本 |
| UX-27 明确三张连拍 | 关闭和开启三张连拍分别按快门，并在连拍中再次按快门 | 关闭时只拍一张；开启时固定拍三张且防重入；结果页保留三张、解释推荐理由并允许改选 |
| UX-28 轻量编辑 | 调整曝光、对比度、饱和度、色温、色调、褪色和强度，依次对比原图、撤销、重做、重置并另存 | 历史结果确定；对比不改历史；另存得到兼容 SDR MediaStore 项；原片内容和 URI 不被覆盖 |
| UX-29 创意失败回退 | 模拟超出解码上限、解码失败、效果导出失败和 MediaStore 失败 | 不崩溃、不占满内存；有原片时回退原片；保存失败给可见错误且不把失败说成成功 |
| UX-30 非目标设备降级 | 在非小米 14 Pro 或低于预览效果能力的环境运行 | 不使用小米私有 API；标准 CameraX 拍摄与原片保存可用；明确提示创意预览能力未验证或不可用 |
| UX-33 参数建议与一键应用 | 构造曝光、失焦、暗景、快速动作、构图和保存策略信号并逐条应用 | 只显示按优先级前三条；EV 使用实际步长；对应控件确实改变；物理动作给原因和动作；不出现 ISO/快门/WB |
| UX-34 分阶段保存 | 分别模拟空间不足、原片成功/配方失败、效果失败、进程重启和阶段重试 | 阶段状态可见；部分成功不回滚；只重试失败阶段；captureId 不变且不重复发布；pending 行和临时文件清理 |
| UX-35 拍后操作 | 对刚保存 URI 依次打开、分享、收藏和移到回收站 | 只作用于本 App 已知 URI；平台确认流程可见；不申请读相册或定位；不支持时不假成功 |
| UX-36 Live 正常路径 | 开启 Live 后保持预览，按一次手动快门 | 会话预检通过后按 HD→SD 尝试四用例并继续指导；发布一个以 `MVIMG_` 开头且以 `MP.JPG` 结尾的单一主文件；SDR 主 JPEG 保持原始颜色，XMP 目录与末尾约 3 秒无声 MP4 布局正确，不另存重复静态原片 |
| UX-37 Live 失败回退 | 分别模拟会话预检、HD/SD 绑定、编码器、空间、裁剪、普通 XMP、混合元数据的 Motion XMP、GainMap、发布失败和进程恢复 | 开关显示真实降级；原始 JPEG 不被改写，最终至多发布一个普通 JPEG；不显示假 Live、不重复发布；临时视频与 pending 行完整清理 |
| UX-39 六类姿势 | 依次选择特写、半身、全身、坐姿、走动和单人互动，并完成、保持、失效、超时和跳过 | 每类只显示适用短口令；有可观察证据的动作在稳定改善后退出；灵感卡不伪装自动完成；一次一个主要动作、最多两个必做动作、快门始终可用 |
| UX-40 低置信度、多人和表情边界 | 构造关键点缺失、遮挡、两张脸、瞬时眨眼、低微笑、侧脸和恢复 | 只按安全顺序给入框、切边、水平或严重曝光；多人不进入单人 Pose；不输出情绪、体型、自然程度或外貌评价；恢复后经稳定门槛更新 |
| UX-41 摄影技巧 | 构造头脚/关节贴边、逆光、错误距离、未标定焦段、杂乱背景、暗景和运动 | 只显示画面可观察或当前公开能力可执行的动作；未标定焦段、精确机位高度、真实深度和系统相机私有夜景能力不显示为已知 |
| UX-42 风格发现与偏好 | 在不同场景打开推荐，依次选择风格、修改强度、切回原图、加入/取消收藏并重启 | 原图始终第一；推荐最多三个且给出一条原因，不自动套用或生成副本；最近最多五个；收藏和最近跨启动保持且不关联照片/人脸 |
| UX-43 人像保守强度 | 在日光、暖光、逆光、暗光、侧脸、多人和采样不足时切换十二种风格及高强度 | 单张可靠人脸时过度颜色/亮度变化会降低全图强度或回原图；未知条件不声称保护；无磨皮、瘦脸、局部光圈或“肤色准确”文案 |
| UX-44 资产完整性与恢复 | 分别破坏临时 JPEG、pending 文件、EXIF、方向、MediaStore 行和 Motion Photo 尾部，并在各阶段杀进程 | 验证失败不得显示成功；无零字节/损坏公开项；恢复不重复发布；原片成功后不因配方或副本失败回滚；0/90/180/270 度方向正确 |
| UX-45 热与长时间运行 | 连续取景 20 分钟、Live 10 分钟、三张连拍 20 组和风格导出 20 次，并模拟 Light/Moderate/Severe/Critical | 按级降低 Pose、背景、预览效果、Live 和连拍负载；降级原因可见；无 ANR/OOM；普通预览、快门和已捕获原片保存不被取消 |

## 3. 完整 P0 验收缺口

FR-15、FR-16、FR-17 目前只有需求级验收摘要和 P0 门禁，没有独立 UX 编号。为避免伪造追踪，本轮不新增或挪用 UX ID；P-1 全部门槛通过、完整 P0 开发获准前，必须补充专属验收用例。该缺口在 [需求追踪矩阵](../traceability/requirements-matrix.md) 中明确标记。

### 9.2 目标机真机矩阵

- P-1、P0 和 P1 只验收小米 14 Pro；其他 Android 机型、折叠屏和平板不进入测试矩阵，也不作兼容承诺。
- 每次验收记录目标机的地区版本、Android 版本、HyperOS 版本、Build fingerprint 和 App 版本；未记录或未实测的系统版本不视为已覆盖。
- 在至少一台小米 14 Pro 上验证冷启动、连续取景 10 分钟、连续拍摄 100 张、前后台切换、权限撤回、相机被占和存储失败；有第二台同型号设备时复跑核心可靠性用例，但不扩展机型范围。
- 其他机型上的问题不阻断第一版；代码仍保留标准 CameraX 能力探测与安全回退，避免无必要地写死厂商私有接口。

本阶段自动化环境没有连接小米 14 Pro，以下状态不得被单元测试替代：

### 9.3 质量门槛

本轮自动化结果（2026-08-31）：`coach:test` Pass、`androidApp:testDebugUnitTest` Pass、ExplainApi .NET 3/3 Pass。该结果不改变本文件任何 instrumented/小米 14 Pro/HyperOS `NotRun`。

- 本地自动化门禁依次运行 `.\gradlew.bat :coach:test` 与 `.\gradlew.bat :androidApp:testDebugUnitTest`；前者覆盖口令安全边界与多人回退，后者覆盖脸框亮度的旋转/裁剪/样本边界、HD→SD 会话顺序、普通 SDR JPEG 选择及 Motion Photo XMP 替换/回退。命令通过只代表 JVM 覆盖，不替代第 9.2 节真机矩阵。
- 第 3.3 节产品指标全部保留原始数据。
- 同机同景与系统相机比较，教练照片不能稳定出现明显更暗、更噪或更糊。
- 扩展模式无法与分析同时工作时，保留分析并回退标准拍照，界面不可黑屏。
- 五秒内出现方向相反提示、重复 TTS、两个动作同屏、快门被指导锁住，均为 P-1 阻断问题。
- 未完成第 3.2 节三组对照实验，不能以内部主观样片代替 Go 决策。
- P1 姿势验收样本中，可观察口令触发精度目标为 ≥90%，改善后的退出响应 p95 ≤1 秒；低置信度和多人样本不得出现单人姿势。样本不足或未记录设备身份时保持 NotRun。
- P1 风格推荐必须稳定、可解释且原图第一；真实颜色、人像保守强度和推荐偏好未经受控样张与人工盲评不得标为 Pass。
- P1 资产完整性矩阵要求普通单拍 100/100 可打开、方向正确、无零字节、无重复和无 pending 残留；该有限样本门禁不替代第 3.3 节长期保存可靠性指标。
- 热降级须在进入 Severe 后 10 秒内降低非必要负载；不得把系统未报告热状态或单次短测当成长期热量通过。
