## 2. 用户、角色与任务

### 2.1 首个目标用户

旅行、约会或日常出门时，拿小米 14 Pro 帮伴侣或朋友拍单人照的拍照新手。他会用系统相机，但不会选机位、控制人物与环境的比例，也不知道怎样开口指导姿势。

Pix、SnapStance 等产品也直接面向伴侣帮拍。因此这只是容易验证的首个任务，不是无人竞争的空白市场。

### 2.2 核心任务

当用户想拍“人物特写”或“人带景”时，App 应在不要求摄影术语、不依赖网络的前提下：

1. 让用户快速确认想拍什么。
2. 只给最重要的一个拍摄者动作。
3. 再给一个被拍者动作。
4. 让用户随时拍下并可靠保存照片。

### 2.3 角色

| 角色 | 定义 | P-1 | P0 |
| --- | --- | --- | --- |
| shooter | 当前拿手机、看屏幕并按快门的人 | 主用户 | 主用户 |
| subject | 画面中的被拍者，主要听语音口令 | 支持一人 | 支持一人 |
| proxy | 临时接过手机代拍的路人或朋友 | 不支持 | 简化界面 |

角色字段是内部组织方式，不是产品护城河。用户界面不显示 shooter、subject、proxy 这些技术名称。

### 2.4 非首个目标用户

- 主要自拍且愿意浏览大量姿势模板的人。
- 需要 RAW、直方图和完整手动参数的摄影爱好者。
- 以美颜、滤镜或 AI 重绘为目的的人。
- 多人合影组织者。
- 需要单反、微单机身或镜头数据库的人。

## 5. 信息架构与主流程

### 5.1 页面

P-1 只有三个用户可感知页面：

| 页面 | 目的 | 不出现 |
| --- | --- | --- |
| 首次说明 | 说明端侧人脸/身体关键点分析并取得同意 | 登录、订阅、课程轮播 |
| 教练取景器 | 确认意图、显示当前动作、拍照 | 模板信息流、评分、多个同时滚动的建议 |
| 保存反馈 | 告知保存成功，或提供可恢复的失败操作 | 强制编辑、强制分享、付费墙 |

后续启动在已同意且权限有效时直接进入取景器，不设置首页。

### 5.2 首次进入

    打开 App
       ↓
    端侧分析说明
       ├─ 暂不使用 → 退出，不申请权限
       └─ 同意并继续
              ↓
         系统相机权限
              ├─ 拒绝 → 解释用途 + “前往系统设置”
              └─ 允许 → 教练取景器

首次说明必须在系统 CAMERA 权限弹窗之前出现。文案说清：

- 本机分析人脸和身体关键点，只用于构图与短口令。
- 不识别“这是谁”，不建立人脸库。
- P-1 不上传取景画面。
- 不同意则不进入取景器。

### 5.3 P-1 主流程

    取景器可操作
       ↓
    顶部轻量选择“人物特写 / 人带景”
       ↓
    最重要的拍摄者动作 1/2（醒目显示；语音开启时也播报）
       ├─ 信号改善 → 自动完成
       ├─ 跳过 → 进入下一步
       └─ 任意时刻按快门 → 直接拍
       ↓
    被拍者动作 2/2（按设置显示字幕 / 播放中文语音）
       ├─ 口令完成或动作失效 → “可以拍了”
       ├─ 跳过 → “可以拍了”
       └─ 任意时刻按快门 → 直接拍
       ↓
    “可以拍了” + 常驻快门
       ├─ 再优化一下 → 最多补一条可选建议
       └─ 按快门 → 保存反馈

新一张照片开始时重置两步预算。用户在任何指导阶段拍摄都视为合法操作，不弹“尚未完成指导”。

### 5.4 取景器布局

竖屏采用稳定的“预览区 + 底部操作区”，指导卡不在画面中追着人脸移动：

    ┌──────────────────────────┐
    │ 退出   人物特写｜人带景  提示方式/设置/闪光 │
    │                          │
    │        相机预览区         │
    │   构图线、水平线、对焦点   │
    │                          │
    ├──────────────────────────┤
    │ 1/2  走近一步  跳过/再优化 │
    │ 1x  已验收长焦  ●快门  最近照片 │
    └──────────────────────────┘

- 竖屏预览使用居中填充并延伸到底部操作区背后，不得因 4:3 / 16:9 预览与长屏比例不同而在操作区上方留下大块黑色空带；允许为填满屏幕裁掉预览边缘，但分析坐标和成片裁切必须通过同一 CameraX `ViewPort` 对齐。
- 底部操作区以两排为主，高度稳定且紧凑，不因提示字数跳动；默认字号下不得占用超过约五分之一的屏幕高度。
- 当前动作最多两行；不能遮挡中央取景区域。
- 横屏时把底部操作区改成右侧操作栏，按钮顺序保持一致。
- 没有建议时显示“可以拍了”，不显示无限旋转的“AI 思考中”。

## 6. 界面与操作规范

### 6.1 取景器组件

| 组件 | P-1 行为 | 验收 |
| --- | --- | --- |
| 意图切换 | 顶部只显示“人物特写 / 人带景”；自动预选但不弹全屏问卷 | 用户手选后本次拍摄会话不再被自动覆盖 |
| 当前动作卡 | 固定在操作区，一次一个动作，使用高对比底色和粗体显示 1/2 或 2/2 | 不与第二条建议同时出现；最多两行；默认设置下不得只显示低对比“可以拍了” |
| 跳过 | 当前动作始终可跳过 | 一次点击进入下一状态，不弹确认 |
| 可以拍了 | 两步结束、两步均跳过或无高置信度建议时显示 | 不要求匹配达标；快门保持醒目 |
| 再优化一下 | 只在“可以拍了”后出现，每张照片最多补一条候选；实时姿势变化产生稳定可选候选时，动作卡改为“发现新建议，可再优化” | 不算必做步骤；补完后入口隐藏；用户仍可直接拍 |
| 提示方式 | 顶部显示“语音+字幕 / 仅语音 / 仅字幕 / 提示关闭”；点按后分别控制当前口令中文语音和被拍者字幕 | 两个开关独立、立即生效并跨启动保持；拍摄者动作卡不受字幕开关影响；语音开启时 shooter / subject 当前口令都可播报 |
| 点按对焦 | 点预览区对焦并显示焦点框 | 对焦失败有可见反馈；不会触发快门 |
| AE/AF 锁定 | 长按预览区锁定当前对焦和曝光；显示“对焦和曝光已锁定”，可一键解除 | 锁定失败、解除、镜头/画幅/模式重绑后的自动恢复都有文字反馈；不能只靠焦点框颜色 |
| EV | 点按对焦后出现短时曝光滑杆；滑杆上下限和步长取当前相机 `ExposureState`；拖动即锁定本次用户选择 | 不支持曝光补偿时不显示假滑杆；口令说调曝光时，用户能当场完成 |
| 快捷焦段 | 只显示小米 14 Pro 经 CameraX/Camera2 能力查询和实拍确认的 1x、长焦等焦段 | 标签与真机实际视角一致；不得把裁切倍率冒充独立光学镜头，也不预设一定是 2x |
| 手动缩放 | 用户可在预览区双指连续放大或缩小，范围以 CameraX 报告能力为准 | 手动缩放不增加虚假光学焦段按钮，口令仍不建议数码猛拉 |
| 可用模式 | “普通”始终可用；人像/HDR/夜景只在扩展可用且支持 `ImageAnalysis` 时出现在模式选择中 | 运行时或绑定失败立即回到普通拍照并说明原因；不得为扩展卸载分析 |
| 构图辅助 | 三分网格与水平仪分别开关，默认开启 | 设置立即生效并跨启动保持；关闭后不再绘制对应叠线 |
| 倒计时 | 关闭、3 秒、10 秒三档；屏幕和音量键共用 | 大号数字可见；倒计时中再次按快门立即取消；不得演变成自动连拍 |
| 画幅 | 4:3 默认，可选 16:9；Preview、Analysis、Capture 使用同一画幅策略重绑 | 切换失败有恢复路径，不允许只裁 UI 而成片画幅不变 |
| 拍摄偏好 | 默认“对焦优先”，可选“拍摄优先” | 前者使用 CameraX 质量优先捕获，后者使用低延迟捕获；两者都不锁快门或停分析 |
| 相机设置 | 汇总提示通道、构图辅助、倒计时、画幅、拍摄偏好和能力驱动模式 | 新增设置跨启动保持；“一键恢复默认”不撤回端侧分析同意，也不删除已拍照片 |
| 闪光 | 顶部显示状态，默认关；P-1 允许关/自动 | 内置口令不要求开启闪光 |
| 快门 | 底部主按钮，除正在捕获和相机不可用外始终可按 | 不受指导、分数或网络状态限制 |
| 音量键 | 等同屏幕快门 | 不改变系统音量后再补拍 |
| 最近照片 | 保存成功后显示本 App 刚拍照片的缩略图；点击交给系统图片查看器 | 只使用本次写入得到的 URI，不申请读取整本相册 |

### 6.2 交互状态

| 状态 | 界面 | 进入下一状态 |
| --- | --- | --- |
| 初始化 | 预览尽快出现；操作区显示“正在准备相机” | 相机可用后进入观察画面 |
| 观察画面 | 快门可按；操作区短暂显示“正在观察画面” | 1.5 秒内有高置信度候选则进入 1/2；明确未看清单人人物时显示“请露出脸，或靠近一点”，不能误报“可以拍了”；人物已可靠识别但无改进建议时才直接“可以拍了” |
| 指导 1/2 | 只显示 shooter 动作 | 信号改善稳定、用户跳过、发生替换条件或用户拍照 |
| 指导 2/2 | 按设置显示 subject 字幕和播放中文语音 | 动作完成/失效、提示通道完成、用户跳过或用户拍照 |
| 可以拍了 | 突出快门，可选“再优化一下”；继续分析画面，不保留已经完成或失效的旧口令 | 用户拍照、请求一条附加建议，或严重成片问题触发替换 |
| 附加建议 | 只显示第三条，不出现 3/3 的必做感 | 语音/提示完成、跳过或拍照后回到“可以拍了” |
| 捕获中 | 快门短暂禁用，显示明确的捕获反馈 | 保存成功或保存失败 |
| 倒计时 | 预览和实时指导继续，大号显示剩余秒数，快门文案变为“停” | 到零进入捕获；再次按屏幕或音量键快门则取消并恢复 |
| 保存成功 | 不弹保存确认页；直接发布照片，并显示勾选、缩略图和“已保存到系统相册” | 1.5 秒后回到新一轮取景；用户也可立即继续 |
| 保存失败 | 保留错误条和“重试保存” | 重试成功，或用户明确放弃后返回取景 |
| 相机错误 | 显示原因、重试和系统设置入口 | 恢复成功后回到取景器；不能停在纯黑屏 |

状态切换要求：

- 可机器判断的 shooter 动作，目标信号改善并稳定至少 500ms 后完成。
- shooter 动作展示 8 秒仍未改善时，不判失败，自动进入下一步；用户仍可随时跳过或拍照。
- subject 动作不是姿势闯关；中文语音播放完成后 1 秒，或仅字幕展示满 2.5 秒，流程可进入“可以拍了”，但仍按实时信号判断该动作是否有效。
- 被拍者字幕不因进入“可以拍了”或经过固定时长自动消失；只在动作完成、动作失效、新口令替换、用户跳过/关闭字幕/拍照、切换意图或开始新一轮时清除。
- 画面信号持续重算；当前口令条件消失或候选改变后，须重新满足候选稳定条件才清除或替换，不能因单帧抖动跳字。
- 两个被拍者提示通道都关闭时，跳过 subject 输出并直接进入“可以拍了”；不得出现无文字、无语音的空等候。
- 单个动作展示至少 1.5 秒；同一句至少 8 秒不重复外放。
- 5 秒内不得给出方向相反的动作。
- 严重过曝、主体切边或镜头遮挡可以替换当前动作，但不能把必做预算增加到三步。
- 镜头遮挡/脏污提示须以连续多帧极暗且低细节为必要条件，文案使用“可能”并让用户检查；普通暗景、纯色墙或单帧抖动不得直接断言镜头脏。
- 相机、权限、保存等系统错误不计入两步预算。

### 6.3 意图操作

P-1 只允许两个意图：

| 画面 | 自动预选 | 操作 |
| --- | --- | --- |
| 后摄一张脸，脸占比较大 | 人物特写 | 顶部两个选项持续可见，用户可一键切换 |
| 后摄一张脸，脸较小且有明显环境主体 | 人带景 | 用户选择后锁定到本次拍摄结束 |

起始脸占比只用于减少点击：人物特写建议区间 12%–25%，人带景建议区间 5%–12%，须用 P-1 样张校准。选择“人带景”后，不能机械切长焦或要求走近到遮住地标。

完整 P0 才增加“只拍景”、前摄和多人安全回退：

- 前摄一张脸：进入自拍包。
- 后摄无脸：预选只拍景。
- 两张脸以上：不进入单人姿势；只给水平、切边和曝光等安全提示。

### 6.4 初始参数与用户控制

- 场景包可以在高置信度稳定后自动应用一次安全的起始参数，具体见第 11.4 节。
- 自动改变镜头、模式或 EV 时，操作区显示两秒可读反馈，例如“已切到长焦”；实际倍率按目标机标定结果显示。
- 后摄快捷焦段以 CameraX 可选择的独立 `CameraInfo` 为入口，并同时要求标准 Camera2 焦距元数据和不同的 `intrinsicZoomRatio`；元数据缺失、候选重复或选择失效时只保留默认后摄，不从机型名、传感器 ID 或小米私有 API 猜倍率。
- 连续缩放上下限来自当前绑定相机的 `ZoomState`；EV 上下限与步长来自当前绑定相机的 `ExposureState`，切换焦段后重新发现并夹紧已有值。
- 用户手动改过某项后，该项在本次拍摄会话中锁定，自动规则不得改回。
- 自动参数调整不计入两步指导预算。
- 同一参数不得在 5 秒内来回切换。

### 6.5 中文语音与字幕

- shooter 动作卡和框线始终可见，不受“被拍者字幕”开关影响；语音开启时 shooter 动作也播报，解决持机者无法持续盯住字幕的问题。
- 当前口令中文语音与被拍者字幕为两个独立开关，首次安装默认都开；允许“语音+字幕 / 仅语音 / 仅字幕 / 提示关闭”四种组合并跨启动保持。
- subject 字幕开启时持续显示到动作完成、失效、替换、跳过、拍照或用户关闭字幕；进入“可以拍了”本身不清除仍有效的动作字幕。
- 关闭中文语音时立即停止当前朗读；若字幕开启则继续字幕流程，若字幕也关闭则立即跳过 subject 输出。
- 系统静音、勿扰或 TTS 失败且字幕开启时，字幕仍可完成流程，并常驻显示当前语音不可用状态；字幕关闭时显示可读失败状态后跳过该条，不擅自开启字幕。
- 连接耳机时走耳机，不对外播放。
- 一次只播一句；shooter / subject 都只播当前稳定口令；实时替换口令时停止已失效的旧句再播放新句，不把新句排在旧句后面。
- 快门音遵循系统，产品不承诺静音快门。

### 6.6 保存反馈与恢复

- 按下快门后立即给出触觉或视觉反馈，不等写入结束才回应。
- 成功后显示本次缩略图与“已保存到系统相册”，不强制进入照片详情页。
- 写入失败必须保留待保存结果，优先允许“重试保存”；不能只弹一条会消失的 Toast。
- 相机被其他应用占用、权限被撤回、镜头初始化失败时显示可执行恢复入口。
- App 不得以黑屏、无限加载或静默失败结束主流程。

### 6.7 P0 代拍简化界面

P-1 不实现。P0 流程：

1. 拍摄者在取景器点“交给别人拍”。
2. App 保留当前意图和构图轮廓，进入简化页。
3. 简化页只显示退出、轮廓、一个大快门和音量键提示；屏幕常亮。
4. 不显示构图、EV、评分或多条字幕；语音默认静音或只在开屏播一句。
5. 代拍者拍完后点“还给我”，回到拍摄者取景器。

这条路径是完整性要求，不宣称独有；PoseOverlay 等产品已有近似陌生人模式。

### 6.8 易用性与无障碍

- 所有主要触控目标至少 48dp。
- 不能只用红/绿颜色表达完成、错误或闪光状态。
- TalkBack 能读出意图、当前动作、中文语音和被拍者字幕开关及状态、闪光、焦段、快门和保存结果。
- 字号跟随系统放大时，动作卡可增高但快门不可被挤出屏幕。
- 竖屏和横屏都验收；折叠外屏和平板不属于第一版验收范围。
- 核心操作不依赖长按、双击或隐藏手势；长按锁 AE/AF 属于增强操作，不是完拍前提。

## 8. 指导引擎与文案

### 8.1 候选、优先级和预算

端侧流程：

    画面信号
       ↓
    用户意图硬过滤
       ↓
    场景规则匹配
       ↓
    最多三条候选：构图 / 光或曝光 / 姿势
       ↓
    节奏器一次呈现一条
       ↓
    默认两条后“可以拍了”

该流程在取景期间持续运行，不是首次命中后冻结：每约 300ms 送入最新信号；已经显示的口令与最新候选不再一致时，重新经过稳定门槛后完成、清除或替换。实时变化只刷新当前动作槽，不增加两步预算；进入“可以拍了”后普通新姿势只更新“再优化一下”的候选，镜头遮挡、主体切边、严重过曝等成片阻断问题仍可优先替换。

Face 与 Pose 结果不得互相作为唯一开关：检测到可靠上半身且未检测到多张脸时，可以输出保守的单人姿势口令；Face 与 Pose 都未看清时输出“请露出脸，或靠近一点”这一检测恢复动作。两张脸以上仍禁止单人姿势口令。

优先级：

1. 相机不可用、保存失败等系统阻断。
2. 镜头遮挡、主体切边、严重过曝等无法正常成片的问题。
3. 最重要的 shooter 机位、构图或曝光动作。
4. 一条 subject 动作。
5. 用户点“再优化一下”后的可选候选。

如果没有可靠的 subject 候选，可以只完成一个 shooter 动作后进入“可以拍了”。“最多两步”不是必须凑满两步。

### 8.2 触发与防抖

| 规则 | 默认值 |
| --- | --- |
| 候选触发 | 条件连续稳定 ≥ 600ms，或连续三次分析成立 |
| 动作完成 | 可判断信号改善并稳定 ≥ 500ms |
| 当前口令失效/替换 | 最新候选连续稳定 ≥ 600ms 或连续三次分析成立后，清除已完成口令或替换为同一动作槽的新口令 |
| 最短展示 | 1.5 秒 |
| 无可靠建议 | 1.5 秒内直接进入“可以拍了” |
| TTS 重复间隔 | 同一句至少 8 秒不重复 |
| 方向冲突 | 5 秒内不得给出相反动作 |
| 用户手动控制 | 改 EV、焦段或意图后，相关自动建议至少静默 3 秒并尊重会话锁定 |
| 低置信度 | 不猜姿势和场景；只保留水平、切边等确定性反馈 |

### 8.3 信号到提示

| 条件 | 可选提示 | 约束 |
| --- | --- | --- |
| 有脸且脸暗、背景亮 | 点一下脸 | 用旋转对齐后的脸框中心亮度与框外背景采样比较；样本不足保持未知；不把“开闪光”作为首选 |
| 人物特写且脸占比 < 12% | 走近一步；小米 14 Pro 的已验收长焦可用时可建议切长焦 | 未通过真机标定的焦段不显示、不建议 |
| 人带景且脸占比 < 5% | 略走近一点，地标要留全 | 不自动切长焦到丢失地标 |
| 人脸贴近画面边缘 | 后退半步，人物别贴画面边缘 | 只依据可见边界，不声称看到了画面外的身体 |
| 人物特写且脸明显落在画面下半部 | 把脸放到上方三分线 | 只用稳定的脸框位置触发；不显示审美分 |
| 人带景且人物仍在画面正中 | 人物放在左或右三分线，景物留另一侧 | 只在用户已选择“人带景”时触发，不强迫所有人像离开中心 |
| 水平倾斜 > 3° | 沿网格放平手机，地平线别歪 | 5 秒内不反向提示 |
| 一张脸且左右转头超过约 18° | 脸转回镜头一点 | 先恢复正脸再判断眼睛；不对侧脸乱猜 |
| 一张正脸且任一眼睛持续低睁眼概率 | 眼睛睁开一点，看镜头 | 连续三帧或 600ms 才提示，瞬时眨眼不触发 |
| 单帧低微笑概率 | 不生成自动口令 | 低微笑不等于紧张、不开心或需要纠正；以后只有用户明确选择“微笑”意图且有独立验收时再立项 |
| 一张脸、肩线过正 | 身体侧一点，脸转回镜头 | 只给 subject |
| 单帧 2D 髋部/脚踝看似居中 | 不生成“重心换到后腿”口令 | 单目 2D 姿态不能可靠判断前后脚承重；保留为人工拍摄灵感，不作自动完成条件 |
| 头明显后仰 | 下巴微收，头略往前 | 低置信度不猜 |
| 场景很暗且手持 | 靠稳手机 | P0 可建议兼容的系统夜景；不建议数码猛拉 |
| Face 与 Pose 都未看清单人人物 | 请露出脸，或靠近一点 | 属于检测恢复动作；不得显示“可以拍了”；两张脸以上不使用该句冒充单人判断 |

### 8.4 文案规则

- 一句只含一个主要动作，优先不超过 16 个汉字。
- 使用手机能执行的词：点脸、拉曝光、切长焦、走近、放平、挪到窗边；倍率文案使用小米 14 Pro 真机标定值。
- 不对新手说光圈、ISO、焦距倒数、开尔文或视觉权重。
- 不评价外貌，不使用“胖、脸大、不上镜”等文案。
- 默认不解释摄影原理；P0 用户点“为什么 / 再讲细”后再展开。
- 每条口令带听众，缺少或非法听众的云端回包必须丢弃。

### 8.5 P0 “再讲细”

- 默认关闭，用户主动点击才联网。
- 首次上传前单独说明：当前预览帧可能含人脸，会离开设备，用完不落库。
- 拒绝、撤回或失败时显示“讲解暂时不可用”，内置指导继续。
- 只上传当前压缩帧和必要信号，不连续上传预览。
- 返回最多三条候选和一句原因，客户端重新做优先级、术语、听众和两步预算校验。
- 供应商可替换，主路径不绑定一家模型。

### 11.3 回归样张

每个启用场景至少四类真机样张：

1. 应该进入该场景。
2. 不应该进入该场景。
3. 必须出现的提示。
4. 禁止出现的提示。

额外要求：

- 每个 P-1 场景至少覆盖小米 14 Pro 真机、竖屏和横屏；每次记录系统与构建版本。
- 两张脸以上不得进入单人姿势匹配，只给水平、切边和曝光等安全回退。
- 无脸、遮挡或骨骼不完整时不猜姿势，不显示匹配分。
- 场景新增或阈值变化必须重跑对应样张；不能只靠开发者现场观察。

### 11.4 场景初始参数

冲突优先级：

**用户明确意图 > 相机方向和人数等硬信号 > 更具体的光位/构图包 > 通用兜底。**

场景高置信度稳定后，可在一次拍摄会话中自动应用一次起始参数：

| 参数 | 规则 | 用户控制 |
| --- | --- | --- |
| 系统模式 | 兼容且能与分析同时工作时使用 Photo / 人像 / HDR / 夜景；否则标准 Photo | 用户可切回 Photo |
| 镜头 | 人物特写可用小米 14 Pro 经真机确认的长焦；人带景默认 1x | 标签使用标定倍率；用户手改后会话锁定 |
| 对焦 | 一张脸时优先脸；无脸时点中景或主体 | 用户可重新点按 |
| EV | 只应用场景起始方向，不持续追着画面自动拉动 | 用户拖动后会话锁定 |
| 闪光 | 默认关 | 状态可见；用户可选自动 |

自动调整必须可见、可覆盖、不可抖动。不得自动套 LUT、美颜、FACE_RETOUCH、数码变焦或自动快门。静态卡与动态教练实验条件使用完全相同的初始参数策略。

| subject | 眼睛睁开一点，看镜头 | 正脸下持续检测到至少一只眼睛低睁眼概率 |
| subject | 身体侧一点，脸转回镜头 | 肩线正对镜头、姿态僵硬 |
| subject | 肩放松 | 肩部明显耸起 |
| subject | 手插口袋，或轻搭在身侧 | 双手僵直或挡住身体 |
| shooter | 点一下脸，再重新构图 | 焦点或测光不在脸上 |
| shooter | 走近一步，减少无关空白 | 人物特写且脸占比过小 |
| shooter | 略走近，让人物更清楚，地标留全 | 人带景且脸占比过小 |

| shooter | 人物放在左或右三分线，景物留另一侧 | 人带景且人物仍在正中 |

规则：

- P-1 首先验证前四条 subject 口令，不要求大姿势库。
- 场景特有句与核口令冲突时，场景特有句优先。
- “换一句”只在当前场景可用句中轮换，不进入姿势商城。
- 所有基础口令免费。
- 不评价外貌，不给姿势分，不等待 100% 匹配。
- 人脸细节只使用端侧 Face 检测提供的正脸角度与睁眼概率；分类缺失、侧脸、多人或置信度不足时不猜。微笑概率不转成“表情需要纠正”。它不是身份识别，也不识别年龄、性别、颜值或复杂情绪。

### 11.6 P1 第二阶段姿势与摄影技巧库

本节属于小米 14 Pro 的 ApprovedSeparate P1 第二阶段，不进入 P-1 三场景对照实验，也不把 P-1 的 12–16 条短口令核扩成必做姿势商城。用户选择某类姿势后，指导仍一次只显示一个主要动作、整轮最多一个 shooter 必做动作和一个 subject 必做动作；其他建议只能经“再优化一下”出现，快门始终可用。

#### 11.6.1 姿势证据与状态

每条姿势必须同时定义：

- 适用类型：特写、半身、全身、坐姿、走动或单人互动。
- 听众、短口令正文和不超过两行的显示文本。
- 进入证据：所需 Face/Pose 关键点、画面边距、时序稳定性和最低可靠度。
- 退出证据：动作改善后能在画面中直接观察的条件。
- 完成方式：可观察退出、定时灵感卡、只提示 shooter 或禁止自动完成。
- 超时、冷却组和低置信度回退；失效口令不得停留或继续播报。

统一状态为：

    Disabled
      → Acquiring
      → Eligible
      → CueActive
      → Satisfied
      → Cooldown

任一阶段证据丢失后进入 LowConfidence；检测到两张脸以上进入 MultiPersonSuppressed。两者都只允许人物入框、切边、水平和严重曝光等安全反馈，不输出单人姿势。进入、退出、证据丢失、超时和冷却的默认时间属于目标机校准参数，不把初始代码常量写成已验收阈值。

#### 11.6.2 六类姿势

| 类型 | 可用短口令 | 可观察进入条件 | 退出/完成条件 | 交付边界 |
| --- | --- | --- | --- | --- |
| 特写 | 脸转回一点 | 单脸可靠且左右转头持续超过校准范围 | 转头回到正脸安全区并稳定 | 可直接实现；阈值需目标机微调 |
| 特写 | 眼睛睁开，看镜头 | 正脸、双眼分类可用且持续低睁眼概率 | 双眼睁开概率恢复并稳定 | 可直接实现；瞬时眨眼不触发 |
| 特写/半身 | 肩放松一点 | 双肩和耳部可靠，归一化肩位持续偏高 | 肩位回到目标机校准区间 | 需小米样张校准 |
| 半身 | 一只手放到身体外侧 | 双腕可靠且持续位于躯干内部或挡住身体 | 至少一只手进入安全外侧且未贴边 | 需姿态、衣着与遮挡样张校准 |
| 半身 | 身体侧一点 | 肩线持续接近正对镜头且脸部方向可用 | 肩/髋二维不对称回到校准区间 | 需校准；不得把 Pose Z 当真实深度 |
| 全身 | 脚下留一点空 | 双踝可靠且靠近画面底边 | 双踝与底边余量恢复 | 可直接实现；边距阈值需校准 |
| 全身 | 手肘和膝盖别贴边 | 腕、肘、膝或踝进入裁切危险区 | 可靠关节离开危险区 | 可直接实现 |
| 全身 | 一只脚向前半步 | 用户选择该灵感且全身稳定可见 | 定时结束或用户跳过 | 不做自动完成；单目二维不足以证明前后脚 |
| 坐姿 | 身体坐直，肩放松 | 髋、膝、踝形成持续坐姿候选且肩髋可见 | 躯干轴和肩位进入校准区间 | 需小米样张和机位校准 |
| 坐姿 | 坐到椅子前半边 | 当前没有可靠椅子或座面检测 | 定时结束或用户跳过 | 只做手动灵感卡，不自动触发 |
| 走动 | 慢慢走一步 | 单人全身、髋与双踝连续可见 | 出现稳定交替步态和位移 | 需时序、模糊和连拍真机校准 |
| 单人互动 | 靠近环境或道具，自然做一个动作 | 用户主动选择互动灵感 | 定时结束或用户跳过 | 不识别具体道具；不扩成双人合影 |

“互动”只指一名 subject 与环境、道具或拍摄者指令的互动灵感。两张脸以上仍属于[合影后期范围](deferred-scope.md#13-合影后期保留第一版不做)，不能因本节出现互动类型而提前多人 Pose。

#### 11.6.3 摄影技巧

| 类别 | 允许使用的证据 | 建议示例 | 禁止或需校准 |
| --- | --- | --- | --- |
| 构图 | 人脸/身体框、三分线、头顶和脚下余量 | 人往右站一点；脚下留一点空 | 不显示审美分 |
| 关节裁切 | 可靠腕、肘、膝、踝到边缘的距离 | 别从膝盖处截断 | 关键点不可靠时不猜 |
| 用光 | 旋转对齐的人脸核心与背景亮度、高光比例 | 让人物转向亮的一边；曝光降一点 | 不把位置当亮度，不默认开闪光 |
| 焦段与距离 | 当前公开相机能力、已验收焦段、脸/身体占比 | 退后一点，再切到已验收长焦 | 不硬编码 2x，不把数码裁切叫光学镜头 |
| 背景空间 | 人脸方向、主体附近边缘密度和局部对比 | 面朝的方向多留一点空间；换个更干净的背景 | 背景杂乱阈值需目标机样张 |
| 机位 | 设备姿态和稳定的人体二维几何 | 手机稍微放低一点 | 不承诺精确相机高度或真实透视深度 |
| 夜景 | 平均亮度、手持稳定性、公开模式能力 | 扶稳手机；先用普通模式 | 不承诺获得系统相机私有夜景质量 |
| 运动 | 关节时序速度、清晰度和连拍状态 | 等动作停一下再拍；明确开启三张连拍 | 模糊阈值和热量需真机校准 |
| 多人安全回退 | 多个人脸框、切边、水平和严重曝光 | 两个人再靠近一点；放平手机 | 不分配单人 Pose，不做表情比较 |

摄影技巧只输出当前取景器能执行、公开 API 能确认或画面可直接观察的动作。背景类别、机位高度、焦段品质、动作自然程度及“更上镜”等无法可靠观测的结论不得伪装成自动判断。

#### 11.6.4 表情边界

- 可直接使用的只有转头、侧倾、眼睛睁开和脸部是否足够可见等中性动作。
- 微笑只在以后增加用户明确选择的“笑脸照”意图、完成独立多帧验收后才能作为动作存在；即使启用，也只能描述“笑容动作”，不能推断开心。
- 不输出自然、紧张、尴尬、疲惫、悲伤、愤怒、上镜程度或其他心理/审美标签。
- 不比较多人表情，不保存 tracking ID，不创建人脸 embedding、身份或长期画像。

#### 11.6.5 低置信度回退顺序

1. 人物是否进入画面。
2. 头顶、脚部或可靠关节是否贴边。
3. 手机是否水平。
4. 人脸是否明显过暗或高光严重溢出。
5. 以上都无可靠证据时保持安静并允许拍照，不用随机姿势填满两步预算。

本节对应 FR-32、FR-33、FR-35 和 UX-39～UX-41；所有自动完成阈值、坐姿/走动准确率、真实帧坐标、多人回退和长期热量在小米 14 Pro 验收前保持 NotRun。
