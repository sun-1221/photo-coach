## 1. 产品结论

### 1.1 一句话

面向拿小米 14 Pro 帮伴侣或朋友拍照的新手的拍中教练：先确认拍摄意图，不打分、不等待完美匹配，默认只给拍摄者和被拍者各一个动作，用户随时可以按快门，并在 30 秒内保存一张真实照片。

### 1.2 要解决的问题

用户会打开系统相机和按快门，但经常遇到：

- 不知道站在哪里、手机应该往哪移动。
- 不知道人物与地标应各占多少画面。
- 不知道该怎样简单、自然地指挥被拍者。
- 建议太多、术语太重时反而错过拍摄时机。
- 第三方相机如果黑屏、卡顿或保存失败，任何指导都失去价值。

本产品首先解决“如何更快完成一次满意的拍摄”，不是建立摄影课程、姿势商城或评分游戏。

### 1.3 核心产品原则

| 原则 | 产品约束 |
| --- | --- |
| 拍下来优先 | 快门始终可用；指导不能锁快门 |
| 最多两步 | 默认一个拍摄者动作 + 一个被拍者动作，之后直接进入“可以拍了” |
| 一次一件事 | 主界面同一时刻只显示一个主要动作 |
| 用户意图优先 | 用户选择后，自动识别不能覆盖本次选择 |
| 不追分 | 不显示美学分、匹配分、准备度分或 100% 对齐 |
| 真实成片 | 使用系统/厂商计算摄影能力；不生成换脸、换姿势或替换原片 |
| 主路径离线 | 意图、两步指导、快门和保存不依赖网络 |
| 隐私最小化 | P-1 只申请相机权限；端侧分析，不识别身份、不建人脸库 |
| 先验证再扩展 | P-1 未过线，不开发完整 P0、姿势库、课程、滤镜或收费 |

### 1.4 已拍板

| 问题 | 决定 |
| --- | --- |
| 首个平台 | Android；P-1、P0 和 P1 只验收小米 14 Pro |

## 2. 用户、角色与任务

### 2.1 首个目标用户

旅行、约会或日常出门时，拿小米 14 Pro 帮伴侣或朋友拍单人照的拍照新手。他会用系统相机，但不会选机位、控制人物与环境的比例，也不知道怎样开口指导姿势。

Pix、SnapStance 等产品也直接面向伴侣帮拍。因此这只是容易验证的首个任务，不是无人竞争的空白市场。

### 2.2 核心任务

当用户想拍“人物特写”或“人带景”时，App 应在不要求摄影术语、不依赖网络的前提下：

1. 让用户快速确认想拍什么。
2. 只给最重要的一个拍摄者动作。
3. 再给一个被拍者动作。
4. 让用户随时拍下并可靠保存照片。

### 2.3 角色

| 角色 | 定义 | P-1 | P0 |
| --- | --- | --- | --- |
| shooter | 当前拿手机、看屏幕并按快门的人 | 主用户 | 主用户 |
| subject | 画面中的被拍者，主要听语音口令 | 支持一人 | 支持一人 |
| proxy | 临时接过手机代拍的路人或朋友 | 不支持 | 简化界面 |

角色字段是内部组织方式，不是产品护城河。用户界面不显示 shooter、subject、proxy 这些技术名称。

### 2.4 非首个目标用户

- 主要自拍且愿意浏览大量姿势模板的人。
- 需要 RAW、直方图和完整手动参数的摄影爱好者。
- 以美颜、滤镜或 AI 重绘为目的的人。
- 多人合影组织者。
- 需要单反、微单机身或镜头数据库的人。

## 3. 产品假设与继续投入门槛

### 3.1 待验证假设

> 对首个目标用户，如果 App 先确认“人物特写 / 人带景”，默认只要求一个拍摄者动作和一个被拍者动作，不显示分数、不等待完美匹配，那么用户能在 30 秒内完成一张比系统相机和静态提示卡更受双方偏好的照片，并愿意在下一次真实拍摄时再次使用。

实时语音、伴侣帮拍、陌生人模式、姿势叠图和端侧分析都已有重叠产品。第一版真正要验证的是：动态指导是否比静态提示卡有增量，以及“两步就拍”是否让用户愿意复用。

### 3.2 P-1 对照实验

- 至少 20 名符合第 2.1 节的首次用户。
- 每人完成室内窗边、室外人带景、逆光人像三个场景。
- 同一设备、同一场景在用户内随机轮换三种条件：系统相机、静态提示卡、动态教练。
- 静态卡与动态教练使用相同的第三方相机管线、初始参数和保存方式；差异只允许来自“是否根据当前画面动态选择提示”。
- 静态卡不分析画面，但仍按与动态教练相同的 1/2、2/2 顺序依次显示一条固定拍摄者动作和一条固定被拍者动作，避免用不同界面节奏干扰实验。
- 每次更换条件时重新站位和构图，避免直接复制上一轮动作。
- 保留原始人数、拍摄次数、失败数、中位耗时和盲评选择，不能只报告百分比。
- 研究员要求的重复测试不计入自然复用。

### 3.3 成功指标

| 维度 | P-1 门槛 | 计算方式 |
| --- | --- | --- |
| 30 秒完拍 | 首次用户保存成功率 ≥ 90% | 从取景器可操作到写入系统相册；不含用户主动退出 |
| 两步预算 | ≥ 80% 的成功拍摄在两个必做动作内完成 | 最多一个 shooter 动作 + 一个 subject 动作；设备错误不计入 |
| 系统相机对比 | 盲评偏好教练照片的比例 ≥ 60% | 系统相机与动态教练照片乱序二选一；拍摄者、被拍者分别记录 |
| 动态增量 | 相比静态卡，盲评偏好至少高 10 个百分点，或中位完拍时间至少缩短 20% | 两项至少通过一项 |
| 自然复用 | 无提醒 D7 真实拍摄再次打开比例 ≥ 30% | 不把研究安排的第二次打开算入 |
| 口令有效 | 可机器判断的口令在 5 秒内使目标信号改善 ≥ 70% | 水平、人脸占比、脸部亮度等；姿势句人工抽检 |
| 错误口令 | 无法执行、听众错误、同屏冲突合计 ≤ 5% | 真机录像复核 |
| 不打扰 | 被拍者认为语音“尴尬或打扰”的比例 ≤ 20% | 拍摄后单题反馈 |
| 性能 | 打开相机 p95 < 1 秒；内置提示 p95 ≤ 300ms | 冷启动、热启动和连续取景分别记录 |
| 保存可靠性 | 快门到系统相册写入成功率 ≥ 99.5% | 真机连续拍摄；失败可见且可重试 |
| 离线 | 飞行模式主路径通过率 100% | 意图 → 两步指导 → 快门 → 相册 |

### 3.4 Go / No-Go

- 第 3.3 节全部通过，才把完整 P0 当发布候选。
- 动态教练不胜过静态卡：停止扩大实时分析，评估改成更简单的拍照清单产品。
- 成片稳定输给系统相机：停止扩教练功能，先修成片链路，或改成不负责拍照的系统相机伴随方案。
- D7 自然复用不过线：不得用滤镜、评分、签到或姿势商城补救核心需求不足。
- 语音打扰超标：停止默认外放，改为首次选择或默认静音后重新验证。

## 5. 信息架构与主流程

### 5.1 页面

P-1 只有三个用户可感知页面：

| 页面 | 目的 | 不出现 |
| --- | --- | --- |
| 首次说明 | 说明端侧人脸/身体关键点分析并取得同意 | 登录、订阅、课程轮播 |
| 教练取景器 | 确认意图、显示当前动作、拍照 | 模板信息流、评分、多个同时滚动的建议 |
| 保存反馈 | 告知保存成功，或提供可恢复的失败操作 | 强制编辑、强制分享、付费墙 |

后续启动在已同意且权限有效时直接进入取景器，不设置首页。

### 5.2 首次进入

    打开 App
       ↓
    端侧分析说明
       ├─ 暂不使用 → 退出，不申请权限
       └─ 同意并继续
              ↓
         系统相机权限
              ├─ 拒绝 → 解释用途 + “前往系统设置”
              └─ 允许 → 教练取景器

首次说明必须在系统 CAMERA 权限弹窗之前出现。文案说清：

- 本机分析人脸和身体关键点，只用于构图与短口令。
- 不识别“这是谁”，不建立人脸库。
- P-1 不上传取景画面。
- 不同意则不进入取景器。

### 5.3 P-1 主流程

    取景器可操作
       ↓
    顶部轻量选择“人物特写 / 人带景”
       ↓
    最重要的拍摄者动作 1/2（醒目显示；语音开启时也播报）
       ├─ 信号改善 → 自动完成
       ├─ 跳过 → 进入下一步
       └─ 任意时刻按快门 → 直接拍
       ↓
    被拍者动作 2/2（按设置显示字幕 / 播放中文语音）
       ├─ 口令完成或动作失效 → “可以拍了”
       ├─ 跳过 → “可以拍了”
       └─ 任意时刻按快门 → 直接拍
       ↓
    “可以拍了” + 常驻快门
       ├─ 再优化一下 → 最多补一条可选建议
       └─ 按快门 → 保存反馈

新一张照片开始时重置两步预算。用户在任何指导阶段拍摄都视为合法操作，不弹“尚未完成指导”。

### 5.4 取景器布局

竖屏采用稳定的“预览区 + 底部操作区”，指导卡不在画面中追着人脸移动：

    ┌──────────────────────────┐
    │ 退出   人物特写｜人带景  提示方式/设置/闪光 │
    │                          │
    │        相机预览区         │
    │   构图线、水平线、对焦点   │
    │                          │
    ├──────────────────────────┤
    │ 1/2  走近一步  跳过/再优化 │
    │ 1x  已验收长焦  ●快门  最近照片 │
    └──────────────────────────┘

- 竖屏预览使用居中填充并延伸到底部操作区背后，不得因 4:3 / 16:9 预览与长屏比例不同而在操作区上方留下大块黑色空带；允许为填满屏幕裁掉预览边缘，但分析坐标和成片裁切必须通过同一 CameraX `ViewPort` 对齐。
- 底部操作区以两排为主，高度稳定且紧凑，不因提示字数跳动；默认字号下不得占用超过约五分之一的屏幕高度。
- 当前动作最多两行；不能遮挡中央取景区域。
- 横屏时把底部操作区改成右侧操作栏，按钮顺序保持一致。
- 没有建议时显示“可以拍了”，不显示无限旋转的“AI 思考中”。

## 6. 界面与操作规范

### 6.1 取景器组件

| 组件 | P-1 行为 | 验收 |
| --- | --- | --- |
| 意图切换 | 顶部只显示“人物特写 / 人带景”；自动预选但不弹全屏问卷 | 用户手选后本次拍摄会话不再被自动覆盖 |
| 当前动作卡 | 固定在操作区，一次一个动作，使用高对比底色和粗体显示 1/2 或 2/2 | 不与第二条建议同时出现；最多两行；默认设置下不得只显示低对比“可以拍了” |
| 跳过 | 当前动作始终可跳过 | 一次点击进入下一状态，不弹确认 |
| 可以拍了 | 两步结束、两步均跳过或无高置信度建议时显示 | 不要求匹配达标；快门保持醒目 |
| 再优化一下 | 只在“可以拍了”后出现，每张照片最多补一条候选；实时姿势变化产生稳定可选候选时，动作卡改为“发现新建议，可再优化” | 不算必做步骤；补完后入口隐藏；用户仍可直接拍 |
| 提示方式 | 顶部显示“语音+字幕 / 仅语音 / 仅字幕 / 提示关闭”；点按后分别控制当前口令中文语音和被拍者字幕 | 两个开关独立、立即生效并跨启动保持；拍摄者动作卡不受字幕开关影响；语音开启时 shooter / subject 当前口令都可播报 |
| 点按对焦 | 点预览区对焦并显示焦点框 | 对焦失败有可见反馈；不会触发快门 |
| AE/AF 锁定 | 长按预览区锁定当前对焦和曝光；显示“对焦和曝光已锁定”，可一键解除 | 锁定失败、解除、镜头/画幅/模式重绑后的自动恢复都有文字反馈；不能只靠焦点框颜色 |
| EV | 点按对焦后出现短时曝光滑杆；滑杆上下限和步长取当前相机 `ExposureState`；拖动即锁定本次用户选择 | 不支持曝光补偿时不显示假滑杆；口令说调曝光时，用户能当场完成 |
| 快捷焦段 | 只显示小米 14 Pro 经 CameraX/Camera2 能力查询和实拍确认的 1x、长焦等焦段 | 标签与真机实际视角一致；不得把裁切倍率冒充独立光学镜头，也不预设一定是 2x |
| 手动缩放 | 用户可在预览区双指连续放大或缩小，范围以 CameraX 报告能力为准 | 手动缩放不增加虚假光学焦段按钮，口令仍不建议数码猛拉 |
| 可用模式 | “普通”始终可用；人像/HDR/夜景只在扩展可用且支持 `ImageAnalysis` 时出现在模式选择中 | 运行时或绑定失败立即回到普通拍照并说明原因；不得为扩展卸载分析 |
| 构图辅助 | 三分网格与水平仪分别开关，默认开启 | 设置立即生效并跨启动保持；关闭后不再绘制对应叠线 |
| 倒计时 | 关闭、3 秒、10 秒三档；屏幕和音量键共用 | 大号数字可见；倒计时中再次按快门立即取消；不得演变成自动连拍 |
| 画幅 | 4:3 默认，可选 16:9；Preview、Analysis、Capture 使用同一画幅策略重绑 | 切换失败有恢复路径，不允许只裁 UI 而成片画幅不变 |
| 拍摄偏好 | 默认“对焦优先”，可选“拍摄优先” | 前者使用 CameraX 质量优先捕获，后者使用低延迟捕获；两者都不锁快门或停分析 |
| 相机设置 | 汇总提示通道、构图辅助、倒计时、画幅、拍摄偏好和能力驱动模式 | 新增设置跨启动保持；“一键恢复默认”不撤回端侧分析同意，也不删除已拍照片 |
| 闪光 | 顶部显示状态，默认关；P-1 允许关/自动 | 内置口令不要求开启闪光 |
| 快门 | 底部主按钮，除正在捕获和相机不可用外始终可按 | 不受指导、分数或网络状态限制 |
| 音量键 | 等同屏幕快门 | 不改变系统音量后再补拍 |
| 最近照片 | 保存成功后显示本 App 刚拍照片的缩略图；点击交给系统图片查看器 | 只使用本次写入得到的 URI，不申请读取整本相册 |

### 6.2 交互状态

| 状态 | 界面 | 进入下一状态 |
| --- | --- | --- |
| 初始化 | 预览尽快出现；操作区显示“正在准备相机” | 相机可用后进入观察画面 |
| 观察画面 | 快门可按；操作区短暂显示“正在观察画面” | 1.5 秒内有高置信度候选则进入 1/2；明确未看清单人人物时显示“请露出脸，或靠近一点”，不能误报“可以拍了”；人物已可靠识别但无改进建议时才直接“可以拍了” |
| 指导 1/2 | 只显示 shooter 动作 | 信号改善稳定、用户跳过、发生替换条件或用户拍照 |
| 指导 2/2 | 按设置显示 subject 字幕和播放中文语音 | 动作完成/失效、提示通道完成、用户跳过或用户拍照 |
| 可以拍了 | 突出快门，可选“再优化一下”；继续分析画面，不保留已经完成或失效的旧口令 | 用户拍照、请求一条附加建议，或严重成片问题触发替换 |
| 附加建议 | 只显示第三条，不出现 3/3 的必做感 | 语音/提示完成、跳过或拍照后回到“可以拍了” |
| 捕获中 | 快门短暂禁用，显示明确的捕获反馈 | 保存成功或保存失败 |
| 倒计时 | 预览和实时指导继续，大号显示剩余秒数，快门文案变为“停” | 到零进入捕获；再次按屏幕或音量键快门则取消并恢复 |
| 保存成功 | 不弹保存确认页；直接发布照片，并显示勾选、缩略图和“已保存到系统相册” | 1.5 秒后回到新一轮取景；用户也可立即继续 |
| 保存失败 | 保留错误条和“重试保存” | 重试成功，或用户明确放弃后返回取景 |
| 相机错误 | 显示原因、重试和系统设置入口 | 恢复成功后回到取景器；不能停在纯黑屏 |

状态切换要求：

- 可机器判断的 shooter 动作，目标信号改善并稳定至少 500ms 后完成。
- shooter 动作展示 8 秒仍未改善时，不判失败，自动进入下一步；用户仍可随时跳过或拍照。
- subject 动作不是姿势闯关；中文语音播放完成后 1 秒，或仅字幕展示满 2.5 秒，流程可进入“可以拍了”，但仍按实时信号判断该动作是否有效。
- 被拍者字幕不因进入“可以拍了”或经过固定时长自动消失；只在动作完成、动作失效、新口令替换、用户跳过/关闭字幕/拍照、切换意图或开始新一轮时清除。
- 画面信号持续重算；当前口令条件消失或候选改变后，须重新满足候选稳定条件才清除或替换，不能因单帧抖动跳字。
- 两个被拍者提示通道都关闭时，跳过 subject 输出并直接进入“可以拍了”；不得出现无文字、无语音的空等候。
- 单个动作展示至少 1.5 秒；同一句至少 8 秒不重复外放。
- 5 秒内不得给出方向相反的动作。
- 严重过曝、主体切边或镜头遮挡可以替换当前动作，但不能把必做预算增加到三步。
- 镜头遮挡/脏污提示须以连续多帧极暗且低细节为必要条件，文案使用“可能”并让用户检查；普通暗景、纯色墙或单帧抖动不得直接断言镜头脏。
- 相机、权限、保存等系统错误不计入两步预算。

### 6.3 意图操作

P-1 只允许两个意图：

| 画面 | 自动预选 | 操作 |
| --- | --- | --- |
| 后摄一张脸，脸占比较大 | 人物特写 | 顶部两个选项持续可见，用户可一键切换 |
| 后摄一张脸，脸较小且有明显环境主体 | 人带景 | 用户选择后锁定到本次拍摄结束 |

起始脸占比只用于减少点击：人物特写建议区间 12%–25%，人带景建议区间 5%–12%，须用 P-1 样张校准。选择“人带景”后，不能机械切长焦或要求走近到遮住地标。

完整 P0 才增加“只拍景”、前摄和多人安全回退：

- 前摄一张脸：进入自拍包。
- 后摄无脸：预选只拍景。
- 两张脸以上：不进入单人姿势；只给水平、切边和曝光等安全提示。

### 6.4 初始参数与用户控制

- 场景包可以在高置信度稳定后自动应用一次安全的起始参数，具体见第 11.4 节。
- 自动改变镜头、模式或 EV 时，操作区显示两秒可读反馈，例如“已切到长焦”；实际倍率按目标机标定结果显示。
- 后摄快捷焦段以 CameraX 可选择的独立 `CameraInfo` 为入口，并同时要求标准 Camera2 焦距元数据和不同的 `intrinsicZoomRatio`；元数据缺失、候选重复或选择失效时只保留默认后摄，不从机型名、传感器 ID 或小米私有 API 猜倍率。
- 连续缩放上下限来自当前绑定相机的 `ZoomState`；EV 上下限与步长来自当前绑定相机的 `ExposureState`，切换焦段后重新发现并夹紧已有值。
- 用户手动改过某项后，该项在本次拍摄会话中锁定，自动规则不得改回。
- 自动参数调整不计入两步指导预算。
- 同一参数不得在 5 秒内来回切换。

### 6.5 中文语音与字幕

- shooter 动作卡和框线始终可见，不受“被拍者字幕”开关影响；语音开启时 shooter 动作也播报，解决持机者无法持续盯住字幕的问题。
- 当前口令中文语音与被拍者字幕为两个独立开关，首次安装默认都开；允许“语音+字幕 / 仅语音 / 仅字幕 / 提示关闭”四种组合并跨启动保持。
- subject 字幕开启时持续显示到动作完成、失效、替换、跳过、拍照或用户关闭字幕；进入“可以拍了”本身不清除仍有效的动作字幕。
- 关闭中文语音时立即停止当前朗读；若字幕开启则继续字幕流程，若字幕也关闭则立即跳过 subject 输出。
- 系统静音、勿扰或 TTS 失败且字幕开启时，字幕仍可完成流程，并常驻显示当前语音不可用状态；字幕关闭时显示可读失败状态后跳过该条，不擅自开启字幕。
- 连接耳机时走耳机，不对外播放。
- 一次只播一句；shooter / subject 都只播当前稳定口令；实时替换口令时停止已失效的旧句再播放新句，不把新句排在旧句后面。
- 快门音遵循系统，产品不承诺静音快门。

### 6.6 保存反馈与恢复

- 按下快门后立即给出触觉或视觉反馈，不等写入结束才回应。
- 成功后显示本次缩略图与“已保存到系统相册”，不强制进入照片详情页。
- 写入失败必须保留待保存结果，优先允许“重试保存”；不能只弹一条会消失的 Toast。
- 相机被其他应用占用、权限被撤回、镜头初始化失败时显示可执行恢复入口。
- App 不得以黑屏、无限加载或静默失败结束主流程。

### 6.7 P0 代拍简化界面

P-1 不实现。P0 流程：

1. 拍摄者在取景器点“交给别人拍”。
2. App 保留当前意图和构图轮廓，进入简化页。
3. 简化页只显示退出、轮廓、一个大快门和音量键提示；屏幕常亮。
4. 不显示构图、EV、评分或多条字幕；语音默认静音或只在开屏播一句。
5. 代拍者拍完后点“还给我”，回到拍摄者取景器。

这条路径是完整性要求，不宣称独有；PoseOverlay 等产品已有近似陌生人模式。

### 6.8 易用性与无障碍

- 所有主要触控目标至少 48dp。
- 不能只用红/绿颜色表达完成、错误或闪光状态。
- TalkBack 能读出意图、当前动作、中文语音和被拍者字幕开关及状态、闪光、焦段、快门和保存结果。
- 字号跟随系统放大时，动作卡可增高但快门不可被挤出屏幕。
- 竖屏和横屏都验收；折叠外屏和平板不属于第一版验收范围。
- 核心操作不依赖长按、双击或隐藏手势；长按锁 AE/AF 属于增强操作，不是完拍前提。

## 8. 指导引擎与文案

### 8.1 候选、优先级和预算

端侧流程：

    画面信号
       ↓
    用户意图硬过滤
       ↓
    场景规则匹配
       ↓
    最多三条候选：构图 / 光或曝光 / 姿势
       ↓
    节奏器一次呈现一条
       ↓
    默认两条后“可以拍了”

该流程在取景期间持续运行，不是首次命中后冻结：每约 300ms 送入最新信号；已经显示的口令与最新候选不再一致时，重新经过稳定门槛后完成、清除或替换。实时变化只刷新当前动作槽，不增加两步预算；进入“可以拍了”后普通新姿势只更新“再优化一下”的候选，镜头遮挡、主体切边、严重过曝等成片阻断问题仍可优先替换。

Face 与 Pose 结果不得互相作为唯一开关：检测到可靠上半身且未检测到多张脸时，可以输出保守的单人姿势口令；Face 与 Pose 都未看清时输出“请露出脸，或靠近一点”这一检测恢复动作。两张脸以上仍禁止单人姿势口令。

优先级：

1. 相机不可用、保存失败等系统阻断。
2. 镜头遮挡、主体切边、严重过曝等无法正常成片的问题。
3. 最重要的 shooter 机位、构图或曝光动作。
4. 一条 subject 动作。
5. 用户点“再优化一下”后的可选候选。

如果没有可靠的 subject 候选，可以只完成一个 shooter 动作后进入“可以拍了”。“最多两步”不是必须凑满两步。

### 8.2 触发与防抖

| 规则 | 默认值 |
| --- | --- |
| 候选触发 | 条件连续稳定 ≥ 600ms，或连续三次分析成立 |
| 动作完成 | 可判断信号改善并稳定 ≥ 500ms |
| 当前口令失效/替换 | 最新候选连续稳定 ≥ 600ms 或连续三次分析成立后，清除已完成口令或替换为同一动作槽的新口令 |
| 最短展示 | 1.5 秒 |
| 无可靠建议 | 1.5 秒内直接进入“可以拍了” |
| TTS 重复间隔 | 同一句至少 8 秒不重复 |
| 方向冲突 | 5 秒内不得给出相反动作 |
| 用户手动控制 | 改 EV、焦段或意图后，相关自动建议至少静默 3 秒并尊重会话锁定 |
| 低置信度 | 不猜姿势和场景；只保留水平、切边等确定性反馈 |

### 8.3 信号到提示

| 条件 | 可选提示 | 约束 |
| --- | --- | --- |
| 有脸且脸暗、背景亮 | 点一下脸 | 用旋转对齐后的脸框中心亮度与框外背景采样比较；样本不足保持未知；不把“开闪光”作为首选 |
| 人物特写且脸占比 < 12% | 走近一步；小米 14 Pro 的已验收长焦可用时可建议切长焦 | 未通过真机标定的焦段不显示、不建议 |
| 人带景且脸占比 < 5% | 略走近一点，地标要留全 | 不自动切长焦到丢失地标 |
| 人脸贴近画面边缘 | 后退半步，人物别贴画面边缘 | 只依据可见边界，不声称看到了画面外的身体 |
| 人物特写且脸明显落在画面下半部 | 把脸放到上方三分线 | 只用稳定的脸框位置触发；不显示审美分 |
| 人带景且人物仍在画面正中 | 人物放在左或右三分线，景物留另一侧 | 只在用户已选择“人带景”时触发，不强迫所有人像离开中心 |
| 水平倾斜 > 3° | 沿网格放平手机，地平线别歪 | 5 秒内不反向提示 |
| 一张脸且左右转头超过约 18° | 脸转回镜头一点 | 先恢复正脸再判断眼睛；不对侧脸乱猜 |
| 一张正脸且任一眼睛持续低睁眼概率 | 眼睛睁开一点，看镜头 | 连续三帧或 600ms 才提示，瞬时眨眼不触发 |
| 单帧低微笑概率 | 不生成自动口令 | 低微笑不等于紧张、不开心或需要纠正；以后只有用户明确选择“微笑”意图且有独立验收时再立项 |
| 一张脸、肩线过正 | 身体侧一点，脸转回镜头 | 只给 subject |
| 单帧 2D 髋部/脚踝看似居中 | 不生成“重心换到后腿”口令 | 单目 2D 姿态不能可靠判断前后脚承重；保留为人工拍摄灵感，不作自动完成条件 |
| 头明显后仰 | 下巴微收，头略往前 | 低置信度不猜 |
| 场景很暗且手持 | 靠稳手机 | P0 可建议兼容的系统夜景；不建议数码猛拉 |
| Face 与 Pose 都未看清单人人物 | 请露出脸，或靠近一点 | 属于检测恢复动作；不得显示“可以拍了”；两张脸以上不使用该句冒充单人判断 |

### 8.4 文案规则

- 一句只含一个主要动作，优先不超过 16 个汉字。
- 使用手机能执行的词：点脸、拉曝光、切长焦、走近、放平、挪到窗边；倍率文案使用小米 14 Pro 真机标定值。
- 不对新手说光圈、ISO、焦距倒数、开尔文或视觉权重。
- 不评价外貌，不使用“胖、脸大、不上镜”等文案。
- 默认不解释摄影原理；P0 用户点“为什么 / 再讲细”后再展开。
- 每条口令带听众，缺少或非法听众的云端回包必须丢弃。

### 8.5 P0 “再讲细”

- 默认关闭，用户主动点击才联网。
- 首次上传前单独说明：当前预览帧可能含人脸，会离开设备，用完不落库。
- 拒绝、撤回或失败时显示“讲解暂时不可用”，内置指导继续。
- 只上传当前压缩帧和必要信号，不连续上传预览。
- 返回最多三条候选和一句原因，客户端重新做优先级、术语、听众和两步预算校验。
- 供应商可替换，主路径不绑定一家模型。

## 10. 约束、隐私与信任

### 10.1 产品与成片约束

- 产品只指挥和叠线，不自研 ISP、RAW、LUT、美颜或生成替换。
- 成片优先使用兼容的系统/厂商计算摄影；无法与实时分析共存时回退标准拍照。

具体 CameraX、ML Kit、扩展兼容和 API 结构以 [architecture.md](architecture.md) 为准。

### 10.2 权限与数据

## 11. 场景与口令库

场景库是规则和文案，不是滤镜库，也不是为每个题材训练一套模型。用户意图是硬过滤条件；每轮最多产生构图、光/曝光、姿势三条候选，再由第 8 节节奏器决定最多两个必做动作。

### 11.1 P-1 三个场景包

| 场景 | 意图与触发 | 安全起始参数 | shooter 候选 | subject 候选 | 禁止 |
| --- | --- | --- | --- | --- | --- |
| 室内窗边 | 一张脸，室内，一侧明显更亮；人物特写 | 兼容时人像，否则 Photo；闪光关；人物特写可一次切到小米 14 Pro 的已验收长焦 | 靠窗半步；点一下脸；窗过白时曝光向下拉一点 | 身体转向窗户；下巴微收 | 开闪光、广角贴脸、反复改 EV |

### 11.3 回归样张

每个启用场景至少四类真机样张：

1. 应该进入该场景。
2. 不应该进入该场景。
3. 必须出现的提示。
4. 禁止出现的提示。

额外要求：

- 每个 P-1 场景至少覆盖小米 14 Pro 真机、竖屏和横屏；每次记录系统与构建版本。
- 两张脸以上不得进入单人姿势匹配，只给水平、切边和曝光等安全回退。
- 无脸、遮挡或骨骼不完整时不猜姿势，不显示匹配分。
- 场景新增或阈值变化必须重跑对应样张；不能只靠开发者现场观察。

### 11.4 场景初始参数

冲突优先级：

**用户明确意图 > 相机方向和人数等硬信号 > 更具体的光位/构图包 > 通用兜底。**

场景高置信度稳定后，可在一次拍摄会话中自动应用一次起始参数：

| 参数 | 规则 | 用户控制 |
| --- | --- | --- |
| 系统模式 | 兼容且能与分析同时工作时使用 Photo / 人像 / HDR / 夜景；否则标准 Photo | 用户可切回 Photo |
| 镜头 | 人物特写可用小米 14 Pro 经真机确认的长焦；人带景默认 1x | 标签使用标定倍率；用户手改后会话锁定 |
| 对焦 | 一张脸时优先脸；无脸时点中景或主体 | 用户可重新点按 |
| EV | 只应用场景起始方向，不持续追着画面自动拉动 | 用户拖动后会话锁定 |
| 闪光 | 默认关 | 状态可见；用户可选自动 |

自动调整必须可见、可覆盖、不可抖动。不得自动套 LUT、美颜、FACE_RETOUCH、数码变焦或自动快门。静态卡与动态教练实验条件使用完全相同的初始参数策略。

### 11.5 短口令核

第一版使用约 12–16 条跨场景短口令，加每个场景一到两条特有句；不按性别、网红风格或模板套装拆库。

| 听众 | 口令 | 触发 |
| --- | --- | --- |
| subject | 下巴微收，头略往前 | 头明显后仰 |
| subject | 脸转回镜头一点 | 左右转头超过可靠分类范围 |
| subject | 眼睛睁开一点，看镜头 | 正脸下持续检测到至少一只眼睛低睁眼概率 |
| subject | 身体侧一点，脸转回镜头 | 肩线正对镜头、姿态僵硬 |
| subject | 肩放松 | 肩部明显耸起 |
| subject | 手插口袋，或轻搭在身侧 | 双手僵直或挡住身体 |
| shooter | 点一下脸，再重新构图 | 焦点或测光不在脸上 |
| shooter | 走近一步，减少无关空白 | 人物特写且脸占比过小 |
| shooter | 略走近，让人物更清楚，地标留全 | 人带景且脸占比过小 |
| shooter | 后退半步，人物别贴画面边缘 | 人脸贴近画面边缘 |

| shooter | 人物放在左或右三分线，景物留另一侧 | 人带景且人物仍在正中 |

| shooter | 请露出脸，或靠近一点 | Face 与 Pose 都未看清单人人物 |

规则：

- P-1 首先验证前四条 subject 口令，不要求大姿势库。
- 场景特有句与核口令冲突时，场景特有句优先。
- “换一句”只在当前场景可用句中轮换，不进入姿势商城。
- 所有基础口令免费。
- 不评价外貌，不给姿势分，不等待 100% 匹配。
- 人脸细节只使用端侧 Face 检测提供的正脸角度与睁眼概率；分类缺失、侧脸、多人或置信度不足时不猜。微笑概率不转成“表情需要纠正”。它不是身份识别，也不识别年龄、性别、颜值或复杂情绪。

## 12. P1、非目标与决策边界

### 12.1 P1 候选

- 样片复刻：通过系统 Photo Picker 导入一张参考图，只用于构图和身体轮廓对齐。
- 连拍选最佳：用户明确启动后连拍，并用端侧信号辅助选择。
- 拍后一句原因：解释刚才为什么走近、放平或调整姿势。
- 第 11.2 节 P1 场景开关。
- 讲解 API 的提示词和供应商替换能力。

P1 不因“已经写进规则库”自动进入排期，必须有 P0 数据支持。

### 12.2 小米 14 Pro P1 创意层（本轮已批准）

本能力是在不改变既有 P-1 实验结论和硬门禁的前提下单独实施的 P1 增强层，只支持并只验收小米 14 Pro。它解决“拍摄者知道该调什么、能得到克制而可撤销的风格、能从一次明确的三张连拍中自行选片、能做轻量修正”四个任务，不把滤镜或连拍数据倒灌成 P-1 过线证据。

参数教练：

- 使用现有端侧信号与当前绑定相机实际报告的能力，按“无法正常成片 > 曝光/对焦 > 稳定性 > 机位/构图 > 输出偏好”排序，最多同时展示 3 张建议卡。
- 可以建议：按 `ExposureState` 步长量化后的精确 EV、点按对焦/测光、AE/AF 锁定或解除、人像/HDR/夜景/普通模式、经小米 14 Pro 标定的焦段与人物距离、靠稳/3 秒倒计时、对焦优先/拍摄优先、明确三张连拍、构图辅助、4:3/16:9 画幅和保存输出策略。
- 能映射现有控件的建议提供一键应用，应用后显示实际结果；走近、放平、靠稳等物理动作必须同时给出当前原因和明确动作，不能伪装成已自动完成。
- 不开放或伪造 ISO、快门速度、光圈、白平衡、开尔文值或完整专业模式；当前能力不支持的 EV、扩展模式、焦段或锁定动作不得显示假入口。

稳定风格：

| 风格 | 用户预期 | 约束 |
| --- | --- | --- |
| 原图 | CameraX 原始成片 | 始终可切回，不做颜色处理 |
| 自然人像 | 轻微柔和、克制暖肤色 | 不磨皮、不瘦脸、不识别人 |
| 柔光人像 | 降低高光反差并轻微褪色 | 只做全图矩阵，不修改面部结构 |
| 清冷人像 | 轻微冷调、压低饱和但保持肤色可辨 | 不做人脸分区或身份规则 |
| 清透旅行 | 适度提亮、增加通透和饱和 | 不把天空或肤色推到明显失真 |
| 森林清新 | 轻微冷绿、柔和对比 | 不识别植物种类，不使用 LUT |
| 日落暖金 | 暖金高光、克制饱和 | 不伪造太阳、天空或局部光效 |
| 美食暖色 | 轻暖、适度饱和与对比 | 不识别菜品或局部重绘 |
| 都市冷调 | 冷色、较低饱和、清晰反差 | 不建立品牌化“电影”预设 |
| 夜色霓虹 | 保留暗部、提高色彩与反差 | 不把夜景自动拉成白昼 |
| 纪实黑白 | 降为黑白、略增对比 | 不改变内容，不生成颗粒或替换细节 |
| 高反差黑白 | 黑白并显著拉开明暗 | 保持可逆预览，不裁掉原片动态范围数据 |

- 预览、导出和编辑必须共享同一套可单测的确定性 4×5 颜色矩阵及强度混合规则；因屏幕色彩管理、CameraX 预览链和 JPEG 编码差异，UI 必须说明“预览为近似效果，导出可能有细微差异”，不得承诺像素完全一致。
- 小米广色域差异不由 App 猜测或重解释：原片主 JPEG 的压缩图像字节保持不变；所有派生 JPEG 明确标为兼容 SDR，不宣称 Ultra HDR 已在小米 14 Pro 验收。
- 十二种风格只做用户主动选择的全图矩阵，不自动套用，也不把“脸框区域颜色变化较小”宣称为肤色保护；局部肤色保护只有在建立脸颊采样、肤色范围和真机样张验收后才能另行立项。
- 不使用 `CameraEffect`、小米私有 API、LUT、FACE_RETOUCH 或重美颜，不能为风格卸载 `ImageAnalysis`。

三张连拍选优：

- 默认关闭；用户在拍摄前明确开启后，一次快门固定顺序捕获三张。捕获期间再次按屏幕或音量键快门不创建第二批。
- 三张原片全部保存。端侧用确定性的清晰度与曝光合理性进行排序，结果页用“更清晰 / 曝光更稳”等理由标出一张推荐；不显示美学分，不自动删除，用户可选任意一张。
- 任一张失败时暂停该批后续捕获，已成功原片继续保留，界面明确显示已完成数量和错误；只有用户明确点“重试保存”后才恢复余下张数，否则终止该批，不得伪装成完整三张。

轻量拍后编辑：

- 以用户所选原片为源，支持曝光、对比度、饱和度、色温、色调、褪色和风格强度；每次修改进入不可变历史，支持撤销、重做和一键重置到进入编辑时的状态。
- 编辑页提供按住或切换“对比原图”，只改变预览，不写入原片或清空历史。
- 唯一保存动作是“另存副本”；禁止覆盖或删除原片。编辑副本的分辨率若受内存上限降采样，保存前必须在界面说明。
- 解码按边界读取并设置明确像素/内存上限；中间 Bitmap 及时释放。解码、颜色处理或编码失败时回到原片预览，MediaStore 失败显示可恢复错误。

非破坏保存与拍后操作：

- 每次按快门创建不可复用的 `captureId`；原片、效果副本、编辑配方和三张连拍序号使用同一 ID 关联，显示名包含稳定 ID 与类型后缀，避免毫秒同名和恢复时重复发布。
- 默认“原片优先”：先发布未覆盖的原始 JPEG，再把所选风格和七项编辑参数作为 App 私有配方保存；默认不生成效果 JPEG。只有用户明确点“另存副本”时生成兼容 SDR 效果 JPEG；另提供用户主动开启的“原片+效果自动保存”策略。
- 保存过程显示空间预检、原片发布、配方保存、可选效果生成/发布等分阶段状态。发生部分成功时保留已成功项，只重试失败阶段；原片发布成功后不得因配方或效果失败而删除或重写。
- 发布写入 `DATE_TAKEN`。派生 JPEG 只复制方向、尺寸、时间和相机厂商/型号等安全 EXIF；不复制定位、缩略图、MakerNote 或可能包含厂商私有数据的未知标签。
- App 私有恢复记录在进入每个不可逆阶段前持久化。异常退出后清理临时文件和 pending MediaStore 行，只恢复未完成阶段；以 `captureId + 阶段` 幂等判断，绝不重复发布。
- 保存前按原片、临时峰值与可选副本估算可用空间；不足时在捕获/发布前给可见错误。效果副本提供“完整质量”和“省空间兼容”两档，两者均为兼容 SDR 且不得修改原片。
- 拍后可对本 App 本次得到的 URI 执行打开、系统分享、收藏和移到系统回收站；不扫描或读取整本相册，不新增定位权限。平台不支持收藏/回收站请求时给出可见说明，不伪装成功。
- 拍照成功后无需用户确认，原片或 Motion Photo 立即完成发布；全屏选片/编辑页不得自动弹出或阻塞下一次快门。用户需要编辑、三张选片或拍后操作时，可从创意菜单主动打开刚拍结果。

无声 Live（Android Motion Photo）：

- 这是 Android 官方 Motion Photo Format 1.0，不命名或冒充 Apple Live Photo。Live 为显式开关，默认无声；绝不新增 `RECORD_AUDIO` 权限或音轨。
- 能力允许时绑定 `Preview + ImageAnalysis + ImageCapture + VideoCapture`，继续实时指导和手动快门。绑定前用 CameraX `SessionConfig` 做组合能力预检，优先 HD、不可用时再试 SD；实际绑定仍失败则回退三用例。Live 模式必须使用普通 Photo，禁止 CameraX Extensions；任何失败都显示原因并回退普通照片，不能保留假 Live 状态。
- 开关启用后维护有严格大小和时长上限的循环临时无声 MP4。按快门时以 CameraX 原始 JPEG 为高分辨率封面，保留快门前后各约 1.5 秒并裁剪为约 3 秒。
- Motion Photo 封面显式使用普通 SDR JPEG，不请求 Ultra HDR。主文件按照官方 v1：向原始 JPEG 写入 `Camera:MotionPhoto=1`、版本和封面时间戳，以及有且仅有 Primary/MotionPhoto 两项的 Container XMP；仅当旧包与本 App 生成的纯 Motion 包一致时整段替换，保证重复调用仍只有一份。若封面含第三方/混合元数据的 Motion XMP、非 Motion XMP、扩展 XMP 或 GainMap，当前版本不得丢弃或盲合并，须回退发布原始普通 JPEG。随后紧密追加 MP4，视频位于文件末尾，显示名符合 `…MP.JPG`。
- 打包、XMP、裁剪或发布任一阶段失败时，清除不完整容器和 pending 行，并可靠发布原始普通 JPEG；恢复记录保证进程重启不重复发布。所有成功、失败、取消和恢复路径都清理超时/超量临时视频。
- Live 主文件保持原始封面颜色；风格和编辑只生成可选静态兼容 SDR 派生副本，避免封面与视频颜色不一致。未在小米 14 Pro 相册验证前不得宣称系统可播放、Ultra HDR 保留或 Live 已验收。

### 12.3 第一版明确不做

- 生成换姿势、换脸或用生成图替换原片。
- P-1/P0 不做重度美颜、自研滤镜、LUT、FACE_RETOUCH 或风格预设；唯一例外是第 12.2 节已批准、非破坏保存的 P1 十二种参数化风格。
- RAW、直方图、单反/微单教学和全品牌镜头数据库。
- 模板信息流、摄影网课、评分水印、对齐百分比、等级、挑战和签到。
- 按男/女或网红风维护数百姿势。
- 达标自动拍、后台连续拍或用户无法立即停止的自动连拍。
- 同步开发 iOS。
- 首版菜单放不可用的“合影 / 即将推出”。
- 第一版不申请麦克风、定位或读取整本相册；无声 Motion Photo 不构成麦克风权限例外。
- 折叠外屏和平板作为发布阻断验收机型。

### 12.4 决策变更规则

- 增加 P-1 页面、权限、必做步骤、测试场景或网络依赖，必须重新评估第 3.2 节实验是否仍可比。
- 将 P1 或后期能力提前，必须写明它解决的已验证问题和对应指标。
- 把任何其他 Android 机型加入 P-1、P0 或 P1 都属于范围扩展，须单独立项并新增对应真机回归，不能用模拟器或“小米 14 Pro 已通过”替代。
- 市场出现相同功能不会自动触发跟进；只根据用户完成效率、成片偏好、复用和可靠性调整。
- 实现遇到限制时，先回到本文修改产品取舍，再更新架构，不能由代码静默改变需求。

## 13. 合影：后期保留，第一版不做

第一版界面和验收不出现合影模式。拍到两张脸以上时，只做安全回退：提示是否有人被切掉、画面是否倾斜和曝光是否严重异常，不进入单人姿势。

后期按顺序评估：

1. 数脸和切边：提示靠近、高个往后、镜头抬高、看镜头；用户明确开启后连拍，用端侧睁眼信号辅助选片，不合成新脸。
2. 二人和三至四人半透明模板：允许拖动缩放，不做多人匹配分。
3. 多人实时骨骼：只有真机通过遮挡、远距离、小孩和高低排测试后才立项。

现在只预留场景枚举 group、检测到的脸数量和可复用的儿童同意模块，不在第一版渲染入口。

### 15.3 结论

- 没有已确认的功能护城河。
- Android、离线、语音、分步、姿势轮廓、代拍、自动拍和真实照片都不能单独写成壁垒。
- shooter / subject / proxy 是实现结构，不是用户可感知的差异化。
- 同类供给拥挤，但不少样本仍是小体量商店应用、Beta 或落地页；现有证据也不能证明需求足够强。
- “最多两步就拍”是主动选择的体验约束，不宣称独有。只有第 3.3 节盲评、完成时间和自然复用过线，才能升级为正式定位。

### 15.4 竞争取舍

| 市场常见做法 | 本产品决定 |
| --- | --- |
| 实时显示多项建议 | 一次一条，默认最多两个必做动作 |
| 就绪分、匹配分和对齐百分比 | 不显示分数，不让用户追分 |
| 稳定后自动拍 | P-1 不做；P0 也默认关闭 |

### 15.5 本轮提示需求的官方依据与边界

| 来源 | 已核对事实 | 对本需求的结论 |
| --- | --- | --- |
| [W3C WCAG 2.2：Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) | 非必要的阅读时限应允许关闭、调整或延长；消失后没有其他获取途径的临时消息会形成时间限制 | 被拍者动作不是必须限时完成的事件，因此不能只显示 2.5 秒就永久消失；字幕应由动作生命周期控制。该网页无障碍标准不是 Android 原生应用的强制合规声明，只作为“给用户足够阅读和反应时间”的设计依据 |
| [Android TextToSpeech](https://developer.android.com/reference/android/speech/tts/TextToSpeech) | `QUEUE_FLUSH` 会丢弃旧播放队列并由新条目替换，`stop()` 会中断当前朗读并清空待播内容 | 实时画面确认旧口令失效时，应停止旧句并播稳定后的新句，不允许把过期指令排队播完 |
| [Android 11 TTS 可见性](https://developer.android.com/about/versions/11/behavior-changes-11) / [小米 TargetSdk 30 适配指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1738) | Android 与小米均要求目标 Android 11+、需要与 TTS 引擎交互的 App 在清单声明 `android.intent.action.TTS_SERVICE` 查询 | P-1 清单补齐该查询，修复目标机上因软件包可见性导致的 TTS 引擎绑定风险；这不是新权限，也不引入口令识别或麦克风 |
| [Android TTS Voice](https://developer.android.com/reference/android/speech/tts/Voice) | TTS 引擎可暴露多个音色，并可标记某个音色是否需要网络 | 优先选择已安装的简体中文离线音色；OEM 引擎未枚举音色时回退其简体中文语言设置，真实外放仍须在小米 14 Pro 验证 |
| [Apple 相机网格与水平仪](https://support.apple.com/guide/iphone/set-up-your-shot-iph3dc593597/ios) / [Pixel Framing hints](https://support.google.com/pixelcamera/answer/14106982) | 两者都把网格、水平或倾斜校正作为拍前取景辅助，而不是拍后评分 | 保留独立网格/水平仪，并把“放平”改成拍摄者能沿网格执行的具体动作 |
| [Nikon 构图指南](https://www.nikonusa.com/learn-and-explore/c/tips-and-techniques/5-easy-composition-guidelines) | 官方指南把三分交点、水平线校正、主体朝向空间作为常见构图起点，同时明确这些是可打破的指导而非硬规则 | 只在“人带景且人物仍居中”时建议左右三分线；中心人像不一律判错，也不加入当前信号无法判断的朝向空间 |
| [CameraX ImageAnalysis](https://developer.android.com/media/camera/camerax/analyze) / [ML Kit Pose Detection](https://developers.google.com/ml-kit/vision/pose-detection/android) | CameraX 可只保留最新分析帧；ML Kit 的 `STREAM_MODE` 用于相关视频帧并利用跟踪降低延迟、平滑检测 | 口令输入应持续取最新画面，而不是第一次命中后冻结；帧丢弃和流模式支持“最新状态优先”，但 300ms 采样、600ms/三帧稳定门槛是本产品的可测防抖参数，须由真机误报率继续校准 |
| [CameraX Zoom](https://developer.android.com/media/camera/camerax/configuration#zoom) | 变焦比必须位于相机报告的最小/最大范围内；越界会失败 | 双指缩放必须尊重小米 14 Pro 实际报告的范围；快捷焦段只显示经真机标定的镜头，模拟器继续用于验证“不支持时不虚报” |

联网复核结论：四种提示组合、字幕按动作生命周期常驻、口令按稳定后的最新画面替换是合理需求；“永远不变地常驻”不合理，动作已完成、失效或被新建议替代时必须清除。外部资料支持设计方向，不证明 600ms/三帧是最优值，该数值仍以第 9 节真机与用户测试为准。

### 15.6 最大市场风险

| 风险 | 验证或停止条件 |
| --- | --- |
| 动态指导不比静态卡有效 | 按第 3.3 节动态增量门槛；不过线停止扩实时分析 |
| 新鲜感不能转成复用 | D7 自然复用 ≥ 30%；不过线不靠玩法补指标 |
| 第三方成片输给系统相机 | 同机同景比较；先修拍照链路或改伴随方案 |
| 两步仍让人分心 | ≥80% 样本在两个动作内拍完；反向提示和重复 TTS 为阻断 |
| 语音让被拍者尴尬 | 打扰比例 >20% 时停止默认外放 |
| 功能迅速被 OEM 覆盖 | 不承诺功能独有，只用完成效率、偏好和复用证明价值 |
